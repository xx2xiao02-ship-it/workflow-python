# 1256 三大模块内部节点治理清单

版本：v1.0  
适用范围：1256 工作流的 61 个可执行节点  
权威注册表：`src/workflow_1256/governance/node_registry.py`

## 1. 目标

把工作流内部节点从“按画布顺序执行”提升为“按数据责任交接”。每个节点必须登记中文名称、节点 ID、所属模块、父批处理、入参、出参、数据责任、外部依赖和当前证据状态。

三大模块的边界固定为：

1. 编导层：负责把文本、TTS 时间线、大镜头和小镜头规划收敛为 `DirectorLockedManifest`。
2. 素材层：负责按编导需求生成、查询、拆分和登记素材，收敛为 `AssetRegistry`。
3. 剪辑层：负责把已登记素材写入剪映草稿，收敛为 `EditManifest`，最终只返回保存后的最新 `draft_url`。

## 3. 编导层治理

### 3.1 数据责任

编导层是唯一可以改变镜头规划、TTS 时间线和素材需求的模块。它必须先完成 TTS 结果、时间线、镜头拆分、字幕和素材需求，再把状态推进到 `DIRECTOR_LOCKED`。

核心数据必须包含：

- 9 个大镜头分组和连续总时间线；
- 17 个小镜头及连续的 `gXX_sYY` 主键；
- 每个小镜头的 `source_text`、`clip_role`、`story_beat`；
- 61 条字幕及所属大镜头；
- 每个镜头和大镜头的素材需求；
- TTS 时间线指纹和来源路径。

### 3.2 内部门禁

- 数组顺序必须沿用上游顺序，不能按模型输出的展示顺序重新排序。
- 时间线统一以微秒存储；`duration` 等按原节点契约保留秒单位，不能混算。
- 每个大镜头必须由其小镜头首尾连续覆盖；所有大镜头必须首尾连续覆盖总时间线。
- TTS 配置或 TTS 结果改变时，必须使字幕、素材时间线和剪辑绑定失效。
- 编导层只产出规划和需求，不写入剪映草稿。

## 4. 素材层治理

### 4.1 数据责任

素材层接收已锁定的 `DirectorLockedManifest`，以 `requirement_id` 为唯一生产目标，以 `asset_id` 为唯一素材记录。素材的真实时长、任务状态、失败信息和 URL 必须独立保存。

### 4.2 任务型节点规则

所有异步素材任务遵循：

```text
创建任务 -> 保存 task_id -> 轮询/查询 -> 记录成功或失败 -> 写入 AssetRegistry
```

创建任务成功不等于素材成功；待查询状态不能填入可用 URL；单项失败必须保留原数组位置和错误字段。

### 4.3 17/18 分支规则

真实成功案例中有 17 个 AIGC 主路线资产和 18 个数字人资产。数字人中有 3 个大镜头覆盖型主持片段，因此它们必须作为大镜头替代路线登记，不能强行压缩成 17 个小镜头的一一映射。

### 4.4 素材层门禁

- `ASSET_MAPPING_ONLY`：仅证明来源、数量、顺序、时间线和需求引用；允许 URL 脱敏。
- `ASSETS_PARTIAL`：部分素材可用，必须列出失败项和可重试性。
- `ASSETS_READY_WITH_WARNINGS`：全部必选素材有可访问定位，但存在可选项或警告。
- `ASSETS_READY`：全部必选素材已验证 URL/本地文件、真实时长和来源。

只有最后两个状态允许进入剪辑生产门禁。

## 5. 剪辑层治理

### 5.1 数据责任

剪辑层不重新解释编导逻辑，只把 `AssetRegistry` 的素材按照 `EditManifest` 的计划绑定到轨道。每次写入剪映插件后，必须使用返回的新 `draft_url` 传给下一个写入节点。

### 5.2 写入顺序

默认顺序为：

```text
创建草稿
 -> AIGC 主路线/数字人替代路线
 -> 解说
 -> BGM
 -> 字幕
 -> 关键帧
 -> 特效（默认关闭）
 -> 保存草稿
 -> 结束
```

特效轨道当前不能进入正式基线：已有本地客户端验证显示错误的 `video_effects` 参数会导致剪映自动退出。因此 `effect_infos`、`add_effects`、`effect_infos_2`、`add_effects_1` 继续登记为 `blocked_by_real_effect_validation`，无特效草稿作为当前安全基线。

### 5.3 剪辑层门禁

- `EDIT_MAPPING_ONLY`：已建立镜头、需求、资产和轨道角色的计划绑定，但没有可验证草稿地址或客户端结果。
- `DRAFT_WRITTEN`：本地或服务端已写入草稿，但未做结构校验。
- `DRAFT_STRUCTURALLY_VALID`：轨道、片段数量、顺序、时间线、最新 `draft_url` 通过结构校验。
- `DRAFT_VALIDATED`：结构校验和客户端打开/播放验收都通过。

只有 `DRAFT_VALIDATED` 才能作为三层数据治理的生产完成状态。

## 6. 版本失效和恢复

| 变更 | 必须失效的范围 | 恢复动作 |
| --- | --- | --- |
| 原文或 TTS 配置改变 | 编导、TTS、时间线、字幕、素材、剪辑 | 回到编导层重新锁定 |
| TTS 结果改变 | 时间线、字幕、素材、剪辑 | 保留旧版本，生成新 `plan_version` |
| 小镜头顺序改变 | 镜头时间线、需求、素材、剪辑 | 重新生成受影响镜头的主键绑定 |
| 单镜头提示词改变 | 目标需求、目标素材、目标剪辑绑定 | 只重做目标 `shot_id` |
| 单素材重新生成且契约不变 | 目标素材、目标剪辑绑定 | 复用原 `requirement_id`，递增 `asset_version` |
| 字幕样式改变 | 字幕剪辑轨道 | 不得修改编导时间线 |
| 特效参数改变 | 特效轨道和草稿校验 | 保持无特效基线可回退 |

恢复不得通过覆盖旧 Manifest 实现；旧版本保留为审计证据。

## 7. 当前执行结论

三层的节点注册和交接门禁已固化，且以同一真实成功执行记录通过专项和全量测试。当前可以继续治理各模块内部的小节点，但下一批应按以下顺序推进：

1. 先治理编导层的真实模型/代码节点，补齐每个节点的真实入参出参和字段来源。
2. 再治理素材层的异步创建、轮询和失败分支，补充不含鉴权的真实成功/失败证据。
3. 最后治理剪辑层的草稿写入；特效保持关闭，直到拿到真实可打开的特效参数。

当前仍不能宣称三层生产验收完成：真实 URL、轨道/片段 ID、最终草稿地址和剪映客户端打开结果仍需外部真实数据验证。
