# 1256 三大模块数据收敛治理准则 v1.0

## 0. 文档定位

本准则是 1256 工作流后续治理、重构、迁移、测试和验收的强制执行基线。治理对象为三个业务模块：

1. 编导模块；
2. 素材模块；
3. 剪辑模块。

共享数据底座只负责数据契约、状态、版本、追踪和恢复，不算第四个业务模块。

本准则高于现有实验性 `DirectorPlan / AssetManifest / DraftPlan` 三层接口。现有接口在完成本准则规定的真实数据映射前，只能作为旁路实验，不得声明为正式主链。

## 1. 总目标

以剪辑草稿为最终数据收敛点，从最终剪辑所需字段反向定义编导和素材数据，使同一个镜头能够从文案规划、TTS、素材生产一直追踪到剪映轨道。

最终必须形成以下可验证链路：

```text
project_id
  → group_id
    → shot_id
      → requirement_id
        → asset_id
          → track_id / segment_id
```

治理完成后必须做到：

- 任一剪映片段都能追溯到具体小镜头、所属大镜头、编导依据和素材任务；
- 任一素材任务都能确认服务于哪个镜头和哪种剪辑用途；
- 任一镜头失败都可以独立重试，不需要重跑整条工作流；
- 文案、TTS、提示词、素材或剪辑参数发生变化时，能够准确计算失效范围；
- 计划时间线、素材实际时长和剪辑实际时间线分别保存，禁止互相覆盖；
- 所有数组保持原始顺序、一一对应关系和失败位置。

## 2. 治理范围和暂不处理范围

### 2.1 本目标范围

- 定义共享 `ProjectManifest`；
- 定义 `DirectorLockedManifest`、`AssetRegistry`、`EditManifest`；
- 定义三个模块的输入、输出、状态机和写入权限；
- 建立稳定主键、版本号、来源路径和事件记录；
- 使用同一条真实成功执行记录完成逐字段映射；
- 建立时间线、失败恢复、版本失效和验收门禁；
- 数据收敛通过后，再进入三个模块内部的小节点治理。

### 2.2 本阶段暂不处理

- 不先优化模型提示词；
- 不替换原模型职责；
- 不改变原 Coze 节点字段、数组顺序和错误语义；
- 不恢复已确认会导致剪映客户端退出的错误特效参数；
- 不把 synthetic 测试描述成真实端到端验收；
- 不因建立新数据结构而删除原始 fixture、适配器或审计报告。

## 3. 总体架构原则

### 3.1 剪辑结果反向设计

编导模块输出的不是普通创意说明，而是剪辑模块可以直接编译的生产蓝图。素材模块不是第二次导演，只负责履行蓝图中的素材需求。剪辑模块不重新创作，只负责按锁定蓝图收敛素材、轨道和草稿结果。

### 3.2 TTS 属于编导模块

TTS 同时承担两项职责：

- 为编导模块提供真实配音时长和大镜头时间线；
- 为剪辑模块提供最终解说音频素材。

只有 TTS 成功并取得真实时间线后，编导模块才允许锁定大镜头和小镜头的微秒时间线。

### 3.3 单一主键链

所有模块必须使用同一套 ID。禁止依靠“数组第几项”作为唯一关联方式；数组索引可以保留，但必须同时带稳定 ID。

### 3.4 计划、实际、写入三值分离

每个镜头至少保留：

- `planned_start_us / planned_end_us / planned_duration_us`：编导锁定值；
- `asset_duration_us`：素材真实时长；
- `edit_start_us / edit_end_us / edit_duration_us`：剪辑实际写入值。

禁止用素材时长覆盖编导时长，也禁止用剪辑结果反写编导计划。

### 3.5 数据来源可审计

所有从原工作流映射的字段必须记录：

- 中文节点名称；
- 原节点 ID；
- `ref_node + path`；
- 原始字段名和类型；
- 时间单位；
- 同一执行记录的证据文件；
- 转换适配器版本。

### 3.6 不静默修复

缺字段、无效时间线、数量不一致、任务失败、URL 为空、素材不兼容时必须明确失败或进入人工确认状态。禁止用空数组、伪造 URL、默认成功状态或自动重排掩盖问题。

## 4. 统一主键和版本规则

### 4.1 必需主键

| 字段 | 作用 | 生成时机 |
|---|---|---|
| `project_id` | 一条视频项目的稳定身份 | 接收文案时 |
| `run_id` | 一次具体执行 | 每次运行时 |
| `group_id` | 大镜头/文案分段 | 总导演分段后 |
| `shot_id` | 小镜头稳定身份 | 镜头精细化后 |
| `requirement_id` | 一项素材需求 | 编导生成素材生产资料时 |
| `asset_id` | 一项真实素材结果 | 素材创建或登记时 |
| `edit_job_id` | 一次剪辑编译和写入 | 剪辑模块启动时 |

建议 ID 形式：

```text
group_id       = g001
shot_id        = g001_s001
requirement_id = g001_s001.video.primary
asset_id       = asset_g001_s001_video_v001
```

### 4.2 必需版本

- `schema_version`：数据契约版本；
- `plan_version`：编导锁定版本；
- `tts_fingerprint`：文本、音色、语速、模型和音频结果摘要；
- `asset_version`：素材重生成版本；
- `edit_version`：剪辑编译版本；
- `adapter_version`：原 Coze 字段映射版本。

同一个稳定 ID 可以产生多个版本，但任何版本不得覆盖历史结果。

## 5. 共享 ProjectManifest

逻辑上统一，物理上分开保存：

```text
project.json
director_manifest.json
asset_registry.json
edit_manifest.json
events.jsonl
```

统一视图至少包含：

```json
{
  "project": {},
  "director": {
    "groups": [],
    "shots": [],
    "requirements": []
  },
  "assets": {},
  "edit": {
    "tracks": [],
    "segments": [],
    "draft": {}
  },
  "status": {},
  "versions": {},
  "provenance": [],
  "validation": {}
}
```

每个模块只能写自己负责的命名空间；跨模块数据只能引用，禁止直接修改。

## 6. 编导模块治理准则

### 6.1 编导模块内部顺序

```text
文案输入
→ 具体画面导演/总导演分段
→ TTS 逐大镜头生成
→ 配音时间线提取
→ 字幕数据细分
→ 全文视觉意图
→ 镜头精细化
→ 小镜头时间线规划
→ 画面类型识别
→ 全局视觉序列编排
→ 首尾帧资料
→ 图片/视频生产提示词
→ 素材需求生成
→ 编导锁定
```

### 6.2 大镜头必需字段

- `group_id`、`group_index`；
- `segment_text`；
- `segment_goal`、`rhythm`、`route_candidates`；
- TTS 音频 URL 或本地路径；
- `tts_fingerprint`；
- `planned_start_us`、`planned_end_us`、`planned_duration_us`；
- 字幕细分结果；
- BGM 情绪和能量意图；
- 所属小镜头 ID 数组，保持时间顺序。

### 6.3 小镜头必需字段

- `shot_id`、`group_id`、`shot_index`；
- `source_text`、`clip_role`、`story_beat`；
- `planned_start_us`、`planned_end_us`、`planned_duration_us`；
- 画面类型：数字人、AIGC、图片、逻辑图、符号画面或其他明确类型；
- 场景、景别、承载方式、视角、构图、视觉重点；
- 首帧、尾帧和参考图要求；
- `motion_seed`；
- 图片提示词和视频提示词；
- 音频、字幕、BGM 和剪辑轨道意图；
- 允许的素材适配策略；
- 素材需求 `requirement_id` 数组。

### 6.4 时间线强制不变量

对每个大镜头：

```text
第一条小镜头.start = 大镜头.start
最后一条小镜头.end = 大镜头.end
相邻小镜头 previous.end = next.start
所有小镜头 duration 之和 = 大镜头 duration
所有 start/end/duration 使用整数微秒
```

对整条视频：

- 大镜头按顺序连续；
- 不允许无声明的空洞或重叠；
- 字幕时间线必须位于对应 TTS 大镜头范围内；
- 小镜头顺序不得与原文、TTS 或字幕顺序冲突；
- 任何舍入余数必须落到明确的小镜头，且记录调整原因。

### 6.5 编导状态机

```text
DIRECTOR_DRAFT
→ TTS_RUNNING
→ TTS_READY
→ TIMELINE_READY
→ SHOTS_READY
→ REQUIREMENTS_READY
→ DIRECTOR_LOCKED
```

任一阶段失败进入 `DIRECTOR_FAILED`，保留失败节点、输入摘要、错误类型和可重试信息。

### 6.6 编导锁定门禁

只有同时满足以下条件才允许 `DIRECTOR_LOCKED`：

- 所有大镜头 TTS 成功；
- 大、小镜头时间线通过连续性和总时长校验；
- 每个小镜头有稳定 `shot_id`；
- 每个必需素材都有 `requirement_id`；
- 所有素材需求都能追溯到一个小镜头和一种剪辑用途；
- 输出顺序与原工作流和同一次真实运行证据一致；
- 没有未确认的默认值、占位 URL 或伪造成功状态。

## 7. 素材模块治理准则

### 7.1 输入边界

素材模块只接受 `DIRECTOR_LOCKED` 的编导版本。编导版本变化后，旧素材结果必须重新计算是否仍然有效。

### 7.2 素材模块职责

- 按 `requirement_id` 创建图片、视频、数字人、BGM 或其他素材；
- 保留创建、等待/轮询、查询、成功和失败全过程；
- 返回真实 URL、本地路径、时长、尺寸、格式和状态；
- 校验素材是否满足编导规格；
- 支持单个需求重试和断点恢复；
- 不修改镜头内容、镜头分类和时间线。

### 7.3 AssetRegistry 必需字段

- `asset_id`、`requirement_id`、`shot_id`、`group_id`；
- `asset_type`、`role`、`mandatory`；
- `status`；
- `remote_url`、`local_path`；
- `asset_duration_us`、宽、高、格式、文件摘要；
- `task_id`、服务商、模型、参数摘要；
- `attempt_count`、创建时间、完成时间；
- `error_type`、`error_message`、`retryable`；
- `validation_result`；
- `asset_version`、`source_plan_version`。

### 7.4 素材状态机

```text
PENDING
→ CREATING
→ PROCESSING
→ SUCCEEDED
→ VALIDATED
```

异常状态：`FAILED_RETRYABLE`、`FAILED_FINAL`、`BLOCKED`、`SKIPPED_OPTIONAL`。

### 7.5 素材完成门禁

- 所有 mandatory 需求均为 `VALIDATED`；
- 每个成功素材存在可访问 URL 或本地文件；
- 实际时长、尺寸和格式已探测，不只相信接口声明；
- 数组数量和顺序与需求清单一致；
- 部分失败保留在原索引，不压缩数组；
- optional 失败有明确降级策略；
- 没有泄露 API Key、Token 或签名凭据。

完成状态为 `ASSETS_READY`；存在可接受的可选项失败时为 `ASSETS_READY_WITH_WARNINGS`；必需项缺失时不得进入剪辑模块。

## 8. 剪辑模块治理准则

### 8.1 输入边界

剪辑模块同时读取：

- 一个 `DIRECTOR_LOCKED` 版本；
- 与其 `plan_version` 对应的 `AssetRegistry`；
- 剪辑模板和草稿配置；
- 当前允许的轨道、关键帧和特效策略。

### 8.2 剪辑模块内部顺序

```text
输入完整性检查
→ 素材与镜头绑定
→ 时间线适配决策
→ 视频轨道规划
→ 数字人轨道规划
→ 音频/BGM/字幕轨道规划
→ 关键帧规划
→ 创建或加载草稿
→ 逐轨道写入
→ 保存草稿
→ 结构校验
→ 剪映客户端打开验收
```

### 8.3 时间线适配策略

编导时间线是目标基准。素材时长不一致时，只能使用编导允许的策略：

- `trim`：裁切；
- `speed`：变速；
- `freeze`：尾帧定格；
- `loop`：循环；
- `pad`：显式留白或补帧；
- `reject`：拒绝并返回素材模块重做。

每次适配必须记录原始时长、目标时长、策略、参数和结果。禁止静默改变镜头边界。

### 8.4 EditManifest 必需字段

- `edit_job_id`、`project_id`、`plan_version`、`edit_version`；
- `shot_id → requirement_id → asset_id` 绑定；
- `track_id`、`segment_id`、素材 ID；
- planned、asset、edit 三套时间值；
- 轨道类型、层级、顺序和混合参数；
- 适配策略和差异；
- 最新 `draft_url` 或本地草稿目录；
- 保存结果；
- 结构校验和客户端打开结果。

### 8.5 草稿写入规则

- 每次写入必须使用上一个剪辑节点返回的最新 `draft_url`；
- 禁止使用早期草稿地址覆盖后续写入；
- `track_id/segment_id` 必须回写到对应 `shot_id`；
- 同一写入请求必须支持幂等识别，避免重试产生重复轨道；
- 当前正式基线保持无特效；
- 恢复特效前必须逐项使用真实兼容参数测试，并验证剪映不会退出。

### 8.6 剪辑完成门禁

只有同时满足以下条件才允许 `DRAFT_VALIDATED`：

- 所有必需镜头均已绑定素材；
- 每个 `shot_id` 都有明确的剪辑落点或显式跳过原因；
- 轨道数量、片段数量和顺序符合计划；
- 时间线连续性和总时长通过；
- 字幕、解说、BGM、AIGC 和数字人轨道均完成结构校验；
- 草稿文件实际存在且 JSON 可读取；
- 剪映客户端能够打开草稿并保持稳定；
- 实际检查画面、时间轴、数字人、字幕位置和音频；
- 未执行真实客户端检查时只能标记 `DRAFT_STRUCTURALLY_VALID`，不得标记最终完成。

## 9. 数据写入权限

| 数据区域 | 编导模块 | 素材模块 | 剪辑模块 |
|---|---:|---:|---:|
| `director.groups/shots/requirements` | 写 | 只读 | 只读 |
| `assets` | 只读 | 写 | 只读 |
| `edit.tracks/segments/draft` | 只读 | 只读 | 写 |
| `events` | 追加 | 追加 | 追加 |
| 历史版本 | 禁止覆盖 | 禁止覆盖 | 禁止覆盖 |

## 10. 版本失效规则

| 变化 | 必须失效的范围 |
|---|---|
| 原文变化 | 编导、TTS、全部素材、全部剪辑 |
| TTS 音色/语速/文本/结果变化 | 时间线、小镜头规划、字幕、全部相关素材和剪辑 |
| 大镜头或小镜头顺序变化 | 受影响镜头之后的时间线、素材绑定和剪辑 |
| 图片/视频提示词变化 | 对应 `requirement_id` 的素材和对应剪辑片段 |
| 同需求素材重生成且规格不变 | 对应素材和对应剪辑片段 |
| 字幕字体、位置变化 | 剪辑模块字幕轨道 |
| BGM 音量变化 | 剪辑模块 BGM 轨道 |
| 关键帧参数变化 | 对应剪辑片段及草稿验证 |
| 特效参数变化 | 特效相关剪辑结果；不得影响无特效基线 |

所有失效必须写入 `events.jsonl`，包含原因、旧版本、新版本和影响对象。

## 11. 错误分类和恢复

错误必须分类，不得统一写成“运行失败”：

- `CODE_ERROR`：本地实现错误；
- `CONTRACT_ERROR`：字段、类型、数量、顺序不符；
- `TIMELINE_ERROR`：时间线无效、重叠、空洞或单位错误；
- `PARAM_ERROR`：外部接口参数错误；
- `AUTH_ERROR`：鉴权错误；
- `NETWORK_ERROR`：超时、DNS、连接失败；
- `PROVIDER_ERROR`：外部服务业务失败；
- `PLATFORM_ERROR`：Coze、剪映或插件平台异常；
- `ASSET_INVALID`：素材无法访问或规格不符；
- `DRAFT_INVALID`：草稿结构错误或客户端无法打开。

恢复原则：

- 只重试失败的最小单元；
- 已验证成功的结果不重复调用付费接口；
- 重试保持相同 `requirement_id/shot_id`，只增加 attempt 和版本；
- 异步任务严格保持创建、轮询、查询、成功/失败分支；
- 不确定外部任务是否成功时先查询，不重复创建；
- 失败达到重试上限后进入 `BLOCKED` 或 `FAILED_FINAL`，等待用户决策。

## 12. 证据等级和状态用词

证据等级必须分开记录：

1. `schema_validated`：Schema 通过；
2. `synthetic_verified`：模拟样本通过；
3. `code_equivalent`：原代码和新实现同输入逐字段等价；
4. `real_fixture_verified`：真实 Coze 脱敏数据回放通过；
5. `transport_live_verified`：真实模型或插件调用通过；
6. `local_draft_structural_verified`：本地草稿结构通过；
7. `client_open_verified`：剪映客户端真实打开通过；
8. `business_acceptance_passed`：画面、时间轴、字幕、数字人和音频人工验收通过。

低等级证据不得冒充高等级证据。测试通过不等于视频业务结果正确。

## 13. 测试和验收要求

### 13.1 契约测试

- 必填字段、类型、枚举和额外字段；
- JSON 对象和 JSON 字符串输入；
- 空数组、字段缺失、无效时间线；
- ID 唯一性和引用完整性；
- 数组数量、顺序和原索引；
- 秒与微秒转换；
- planned/asset/edit 三套时间值不被覆盖。

### 13.2 状态机测试

- 成功路径；
- 单项失败；
- 部分失败；
