证据范围：同一条已保存的 Coze 成功执行记录的脱敏 fixture  
时间单位：微秒（`microseconds`）

## 1. 结论

本报告已经把同一条真实成功执行记录映射为正式的 `ProjectManifest`，并通过 Python 契约校验和 JSON Schema 校验。

Manifest 同时保存了 18 条机器可检查的字段映射记录，每条记录包含来源节点、源路径、目标路径、源/目标类型、数量关系、顺序策略、时间单位和证据状态。

当前证明的是“真实执行记录的字段、数组顺序、时间线和跨模块引用能够收敛到统一数据底座”。它不是 Coze 全链路重跑，也不是剪映客户端打开验收。URL、轨道 ID、片段 ID 和草稿地址在 fixture 中已脱敏，因此资产状态只能是 `ASSET_MAPPING_ONLY`，剪辑状态只能是 `EDIT_MAPPING_ONLY`。

```text

  9 个大镜头

        ├─ 每个小镜头：AIGC 视频 + 首帧要求 + 视频提示词要求
        └─ 每个大镜头：解说 + 字幕 + 可选数字人替代路线

素材层
  17 个 AIGC 主路线资产
  18 个数字人资产（不是 17 个小镜头的一一替代）
  9 个解说资产
  1 个 BGM 资产

剪辑层
  17 个 AIGC 主路线镜头绑定
  数字人按大镜头覆盖关系保留为替代路线
  字幕、解说、BGM 作为独立轨道计划
```

## 4. 关键映射规则

### 4.1 主键

- 项目：`project_id = 1256-7668196429877870619`
- 执行：`run_id = 7668196429877870619`
- 大镜头：`g01` 至 `g09`
- 小镜头：`g01_s01` 这类稳定主键；每个大镜头内从 `s01` 连续编号
- 字幕：按原 `new_segments/new_timelines` 顺序生成 `caption_001` 至 `caption_061`
- 素材：由 `asset.<scope>.<role>.vXXX` 组成，并保留 `requirement_id`

### 4.2 时间线

- 所有正式契约只接受整数微秒。
- 总时间线为 `[0, 111672000)`。
- 9 个大镜头首尾连续覆盖总时间线。
- 每个大镜头的小镜头首尾连续覆盖所属大镜头。
- 每个字幕时间线必须落在所属大镜头内。
- 素材的 `actual_timeline` 与剪辑的 `planned_timeline` 分开保存；不能用规划时长冒充真实素材时长。

### 4.3 数字人 18 段的处理

真实记录中数字人是 18 段，其中 15 段为 Seedance 类片段，3 段为数字人主持片段。3 段主持片段覆盖的时间窗口位于：

- `g02`：`22309674–30840000`
- `g05`：`66960000–75521228`
- `g08`：`100656000–109416000`

因此数字人不能被压缩成 17 个小镜头的一一数组。治理层将其保存为大镜头范围的可选替代路线，保留 18 条原顺序资产记录；剪辑层只有在选择该替代路线后，才允许重新生成对应大镜头的绑定。

## 6. 证据和限制

本映射代码只读取 `samples/real` 中已经保存的脱敏 fixture，不调用外部模型、插件或鉴权服务，不修改 Coze 原始压缩包。由于 URL、轨道 ID、片段 ID 和草稿地址已脱敏，不能把本报告的结果表述为“真实草稿已可访问”或“剪映已通过打开验收”。

下一道门禁必须补充一条未脱敏但不暴露鉴权信息的成功记录：只保留可验证的 URL/ID 形态、素材文件存在性、草稿目录结构和客户端打开结果。补齐后，状态才能从映射态推进到 `ASSETS_READY`、`DRAFT_STRUCTURALLY_VALID` 或 `DRAFT_VALIDATED`。
