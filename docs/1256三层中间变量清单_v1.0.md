# 1256 三层中间变量清单 v1.0

## 1. 使用规则

本清单是 Daily_Update_Te（工作流 `7667938827822825515`）三层数据的交接字典。变量分为：

1. 编导层：决定“讲什么、何时讲、每个小镜头需要什么素材”。
2. 素材层：按已锁定需求生产、查询、登记媒体，不得改写语义和计划时间线。
3. 剪辑层：把已登记媒体和字幕写入剪映，生成 Windows 原生草稿；不得反向修改编导决策。

统一约束：

- 计划时间线、素材实际时长、剪辑写入时间线必须分字段保存；
- 时间单位统一为 `microseconds`（微秒），CapCut Mate 和剪映写入不得混用毫秒；
- 数组默认保持输入顺序，并通过 `source_index`、`shot_id`、`requirement_id`、`asset_id` 追踪；
- `draft_url` 只能来自当前写入节点的最新返回值；Windows 原生本地草稿使用 `local_draft_path`，不能把两者混为一谈；
- `synthetic`、`fixture_observed`、`ASSET_MAPPING_ONLY`、`DRAFT_STRUCTURALLY_VALID` 是不同证据等级，不得互相冒充。

## 2. 三层总交接

| 层级 | 正式交接对象 | 上游输入 | 核心输出 | 允许修改 | 禁止修改 |
|---|---|---|---|---|---|
| 编导层 | `DirectorLockedManifest` | `text`、TTS 时间线、画面导演结果 | 大镜头、小镜头、字幕时间线、素材需求 | 编导内部中间变量 | 已锁定后的语义、shot 时间线、需求 ID |
| 素材层 | `AssetRegistry` | `DirectorLockedManifest.requirements` | 任务状态、媒体地址、实际时长、媒体证据 | 任务状态、资产地址、实际媒体信息 | `segment_text`、`shot_id`、计划时间线、需求含义 |
| 剪辑层 | `EditManifest` | `DirectorLockedManifest + AssetRegistry` | 轨道映射、写入 ID、草稿地址/本地草稿路径、结构验收 | 轨道与片段绑定、剪辑写入结果 | 编导字段、素材原始结果、Mac/iOS 模板身份 |

## 4. 素材层中间变量

| 变量 | 类型/单位 | 生产节点 | 下游消费者 | 约束 |
|---|---|---|---|---|
| `MaterialRequirement` | 正式对象 | 编导收口 | 各素材任务 | 描述“要生产什么”，不放真实媒体地址 |
| `requirement_id` | `String` | 编导层 | 全素材任务、剪辑绑定 | 全局唯一，不因重试改变 |
| `asset_type` / `role` | `String` | 编导需求 | 素材任务路由 | 区分 video、image、audio 与 first_frame、narration、bgm 等角色 |
| `route` | `String` | 编导层 | 素材服务 | 例如 AIGC、首帧、数字人替代、TTS、BGM；只表达生产路线 |
| `prompt` / `ref_image` / `ref_image_e` / `ref_image_f` | `String/Array` | `184922`、`170263`、`113743` | 图片/视频服务 | 生产输入，不得写入剪辑层作为语义字段 |
| `task_id` | `String` | `142186`、`139653`、`173596`、`186546` | 对应查询节点 | 创建成功不等于素材成功，必须继续 query/poll |
| `status` | 状态字符串 | create/query | `AssetRegistry` | `PENDING`、`PROCESSING`、`SUCCEEDED`、`FAILED_*` 等状态要原样登记 |
| `output_url` / `video_url` / `image_url` / `audio_url` | `String` | 各素材查询/合成节点 | 资产登记、剪辑编译 | 外部 URL 必须经过可访问性和媒体类型校验 |
| `asset_duration_us` | `Integer` / 微秒 | 素材探测 | 剪辑层 | 真实时长；不得覆盖编导规划时长 |
| `actual_timeline` | `TimeWindow` / 微秒 | 素材探测/合成 | 剪辑绑定 | 真实媒体覆盖范围，和 `planned_timeline` 分开 |
| `source_index` | `Integer` | 批处理/循环 | 数组对齐 | 保留原批处理顺序，不能以 URL 排序替代 |
| `evidence_level` | 状态字符串 | 素材登记 | 验收 | `synthetic`、`fixture_observed`、真实可访问等必须明确区分 |
| `AssetRecord` | 正式对象 | 素材层 | `AssetRegistry` | 一个资产的来源、状态、地址、实际时长和错误信息 |
| `AssetRegistry` | 正式对象 | 素材收口 | 剪辑层 | 必须可由 `DirectorLockedManifest` 校验，状态至少为 `ASSET_MAPPING_ONLY` |

关键异步中间变量：

- AIGC 视频：`video_prompt → task_id → query.status → video_url → asset_duration_us`；
- 首帧：`prompt/ref_image → task_id → image_url`；
- BGM：`bgm_tasks → AudioUrl_list → merged_audio_url → actual_timeline`；
- TTS：`text/speaker_id/speed_ratio → audio_url → narration audio_infos`；
- 数字人：`audio/image/prompt → task_id → output_url`。本阶段允许数字人跳过，但必须登记为 `SKIPPED_OPTIONAL` 或占位图资产，不能伪造成功。

## 5. 剪辑层中间变量

### 5.1 进入剪辑层前

| 变量 | 类型/单位 | 来源 | 用途 |
|---|---|---|---|
| `DirectorLockedManifest` | 正式对象 | 编导层 | 提供 shot、caption、planned timeline、需求关系 |
| `AssetRegistry` | 正式对象 | 素材层 | 提供实际媒体、状态、地址、实际时长 |
| `EditingLayerPlan` | Python 正式对象 | `compile_editing_layer` | 剪辑层编译后的全量中间变量快照 |
| `native_items` | `Array<Object>` | `EditingLayerPlan` | Windows 本地写入项：`asset_id`、`native_path`、轨道名、窗口、实际时长 |
| `captions` | `Array<Object>` | `DirectorLockedManifest.captions` | 转成剪映字幕片段，和 `caption_id` 保持映射 |
| `tracks` | `Array<Object>` | `EditingLayerPlan` | 固定轨道顺序、轨道类型和条目数量 |
| `capcut_payloads` | `Object` | `EditingLayerPlan` | 只读投影到 CapCut Mate 节点字段；不把本地路径伪装成 URL |

### 5.2 剪映小助手写入中

| 变量 | 节点/方法 | 输入 | 输出/验收 |
|---|---|---|---|
| `width`、`height`、`fps` | `DraftFolder.create_draft` | 画布配置 | 返回的 `platform.os` 和 `last_modified_platform.os` 必须都是 `windows` |
| `draft_name`、`local_draft_path` | `DraftFolder` / `draft_meta_info.json` | 草稿身份 | 只更新草稿身份，不覆盖 Windows 模板平台字段 |
| `video_infos` | `AIGC动画*` 等效轨道 | 本地视频 + 微秒窗口 | 写入视频轨，保存真实媒体路径 |
| `first_frame` | 首帧参考轨 | 图片资产 + shot 窗口 | 作为参考轨写入，不替代主视频 |
| `character_placeholder` | 主角占位轨 | 主角形象图 | 数字人未调用时的显式占位，不冒充数字人成功 |
| `audio_infos` | `解说*`、`背景音乐*` | TTS/BGM + 微秒窗口 | 两条音频轨，音量等二级参数单独保留 |
| `captions` | `字幕*` | `caption_id/text/start/end` | 字幕轨与 `caption_id` 一一对应 |
| `track_id` | 剪映草稿 JSON | 轨道写入后 | 只记录实际生成 ID，不提前编造 |
| `segment_id` / `text_id` / `audio_id` / `video_id` | 剪映草稿 JSON或服务响应 | 片段写入后 | 保持与输入数组顺序一一对应 |
| `effects`、`transitions` | 特效/转场节点 | 当前稳定基线 | 默认空数组；未完成真实 Windows 验收前禁止写入 |
| `EditManifest` | 剪辑层收口 | 轨道和片段写入结果 | 状态从 `EDIT_MAPPING_ONLY` 到 `DRAFT_STRUCTURALLY_VALID`，不表示客户端已播放验收 |

## 6. 剪辑层代码入口

实现文件：`src/workflow_1256/editing_layer.py`

| 入口 | 是否有副作用 | 作用 |
|---|---:|---|
| `compile_editing_layer(director, assets)` | 否 | 校验两个正式交接对象，生成 `EditingLayerPlan`、轨道和 CapCut Mate 字段投影 |
| `validate_windows_native_plan(plan)` | 否 | 检查 Windows 平台、本地文件存在、特效/转场关闭 |
| `write_windows_native_draft(plan, ...)` | 是 | 调用剪映小助手 `DraftFolder.create_draft`，复制媒体、写入轨道、保存并读取 `draft_content.json` 验收 |
| `EditingLayerPlan.to_edit_manifest()` | 否 | 生成 `EDIT_MAPPING_ONLY` 的正式剪辑交接对象 |

本实现明确不调用 HTTP `/openapi/capcut-mate/v1/create_draft` 作为 Windows 原生创建方式。HTTP 节点适配器仍可用于字段契约和服务端实验，但 Windows 客户端草稿的正式入口是：

`capcut-mate/src/pyJianYingDraft/assets/draft_content_template.json` → `pyJianYingDraft.DraftFolder.create_draft` → `VideoSegment/AudioSegment/TextSegment` → `script.save()`。

## 7. 验收门禁

### 代码级验收

- 编导状态为 `DIRECTOR_LOCKED`；
- `AssetRegistry.validate_against(director)` 通过；
- 所有写入时间线为微秒整数；
- `native_items` 中每个视频、音频、图片均有可读本地文件；
- 当前稳定基线 `effects=[]`、`transitions=[]`；
- 输出 `EditManifest` 能通过 `validate_against`。

### Windows 草稿结构验收

- 草稿由剪映小助手项目的 `DraftFolder.create_draft` 创建；
- `platform.os == windows`；
- `last_modified_platform.os == windows`；
- `draft_content.json` 存在，所有媒体路径存在；
- 轨道、片段、字幕数量与 `EditingLayerPlan` 一致；
- 结构验收通过只能记为 `DRAFT_STRUCTURALLY_VALID`，还需人工打开客户端并播放后才能升级为 `DRAFT_VALIDATED`。
