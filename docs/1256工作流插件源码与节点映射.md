## 第一个实际迁移节点：创建草稿

### Coze 节点契约

工作流配置中该节点显式传入：

```json
{
  "height": 1920,
  "width": 1080
}
```

节点输出配置为：

```json
{
  "draft_url": "string",
  "tip_url": "string"
}
```

### 插件源码逻辑

1. 请求模型中的 `width` 默认值是 1920，`height` 默认值是 1080，且都要求大于等于 1。
2. 服务层生成时间戳加随机 ID 的草稿目录名。
3. 从 `default2` 模板复制草稿目录。
4. 修改画布宽高，开启双文件兼容模式。
5. 写入空的 `main_track` 视频主轨道并保存。
6. 更新草稿缓存，返回草稿 URL。
7. 路由层额外注入 `tip_url`。

### 尚未宣称等价的部分

`draft_url` 包含运行时生成的时间戳和随机 ID，且创建动作会写入插件服务端模板目录。因此本地 Python 适配器可以先验证输入/输出契约和响应解析，但只有同一组真实 Coze 入参、插件响应和草稿文件结果齐备后，才能进行代码级/行为级验收。

这里存在一个需要后续核对的版本差异：工作流导出配置中只登记了 `height` 和 `width`，而运行页面显示了空的 `user_id` 输入行；capcut-mate 当前源码的 `CreateDraftRequest` 也只声明 `height` 和 `width`。在取得插件实际 HTTP 请求体之前，不把 `user_id` 猜测性加入业务逻辑。
