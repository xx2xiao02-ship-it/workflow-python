## 3. 输入输出契约

Schema：[`schemas/prompt_generation.schema.json`](../schemas/prompt_generation.schema.json)

### 输入

| 字段 | 类型 | 来源 |
|---|---|---|
| `plan_out_list` | object[] | “生成视频提示词撰写”→`plan_out_list` |
| `ref_image` | object[] | “首尾帧顺延”→`ref_image` |
| `clip_duration` | object[] | “首尾帧顺延”→`clip_duration` |

每组 `plan_out_list` 通常包含 `plans`；每个计划包含 `shot_index`、`duration`、`stages`。参考图组通常为 `{ "ref_image": string[] }`，时长组通常为 `{ "clip_duration": number[] }`。原代码同时保留多层 JSON 字符串解析兼容行为。

### 输出

原始字段顺序保持不变：

1. `video_prompt`: string[]
2. `int_duration`: integer[]，秒
3. `ref_image_f`: string[]，每个镜头首帧
4. `ref_image_e`: string[]，下一镜头首帧；没有下一帧时为 `""`
5. `camera_fixed`: boolean[]
6. `error`: string

所有镜头输出数组按原始 `shot_index` 排序后逐项对齐。新实现没有增加字段、删除字段或改变数组顺序。

## 4. 原行为核对

- 输入值最多解析 5 层 JSON 字符串；非数组/非对象按原代码转换为空容器。
- `shot_index` 无效、越界或重复时回退到当前位置，并按最终索引排序。
- `duration` 使用 `ceil(float(value))`；小于 4 秒归一化为 4 秒，大于 12 秒归一化为 12 秒。
- `plan.duration` 无效时优先使用对应 `clip_duration`，两者都无效时使用 4 秒，并记录原错误文本。
- 时间线只保留最多 3 个有效阶段；时间范围无效时使用原代码的权重回退规则，并保证最后一段结束于完整时长。
- 缺少阶段动作时使用原代码默认阶段；后续阶段的动作按原代码补充前一阶段衔接语句。
- `ref_image_f` 和 `ref_image_e` 按原代码逐镜头装配；最后一个尾帧为空字符串。
- 无有效组时返回 6 个固定输出字段，并将错误写入 `error`；不抛出额外异常。
