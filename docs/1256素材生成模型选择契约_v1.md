# 1256 素材生成模型选择契约 v1

## 结论

素材生成层提供两个视频模型选择值，并保留自动降级：

| 能力 | 用户可选值 | 系统默认值 | 实际调用规则 |
| --- | --- | --- | --- |
| 首帧/图片生成 | `auto`、`image2` | `auto` | `image2` 映射到已验证的图片 API 模型 ID `gpt-image-2` |
| 视频生成 | `auto`、`seedance_1_5_pro`、`seedance_1_0_pro` | `auto` | `auto` 或显式 1.5 先调用 Seedance 1.5 Pro；额度、权限、限流或模型/接入点不可用时降级到 1.0 Pro |

官方模型 ID 由 transport 统一维护：

- Seedance 1.5 Pro：`doubao-seedance-1-5-pro-251215`
- Seedance 1.0 Pro：`doubao-seedance-1-0-pro-250528`

业务字段不把 API Key 写入请求或页面；模型 ID 也可以由项目环境变量覆盖为 Endpoint ID。

## 入参位置

工作流入口允许传入：

```json
{
  "text": "文案",
  "image_model": "auto",
  "video_model": "auto"
}
```

直接调用素材节点时，同名字段也可传入：

- 首帧批处理 `184922`、图片任务 `142186`：`image_model`
- 视频批处理 `110697`、视频任务 `139653`：`video_model`

缺省或传入 `auto` 时，系统先按 1.5 Pro 路径执行；只有达到降级条件才进入 1.0 Pro。显式传入 `seedance_1_0_pro` 时不调用 1.5。

## 四套鉴权装配

Seedance transport 支持按文档顺序装配最多四套鉴权：主、备用、第三、第四。每一套鉴权都会按同一顺序参与当前模型阶段：

1. 鉴权 1 → 1.5 Pro
2. 鉴权 2 → 1.5 Pro
3. 鉴权 3 → 1.5 Pro
4. 鉴权 4 → 1.5 Pro
5. 鉴权 1 → 1.0 Pro
6. 鉴权 2 → 1.0 Pro
7. 鉴权 3 → 1.0 Pro
8. 鉴权 4 → 1.0 Pro

“无额度”不是只切换 Key，也不是直接跳过 1.5：当前 1.5 鉴权失败后先尝试剩余 1.5 鉴权，全部不可用才进入 1.0。成功创建任务后保存任务 ID，后续查询复用该任务，不重复计费。

本机环境变量支持：

```text
SEEDANCE_PRIMARY_API_KEY
SEEDANCE_BACKUP_API_KEY
SEEDANCE_THIRD_API_KEY / SEEDANCE_AUTH3_API_KEY
SEEDANCE_FOURTH_API_KEY / SEEDANCE_AUTH4_API_KEY
SEEDANCE_MODEL_1_5_EP   # 可选，覆盖默认 1.5 Model/Endpoint ID
SEEDANCE_MODEL_1_0_EP   # 可选，覆盖默认 1.0 Model/Endpoint ID
```

鉴权文档解析器只返回 Seedance 区段中的候选 Key；源码、日志、状态文件和网页不得保存完整 Key。

## 鉴权/参数边界

- `video_model` 只表达业务选择，不允许用户借此绕过鉴权。
- 401、403、429、5xx、额度/限流/余额/模型不可用/接入点不可用等账号或资源级错误允许切换下一候选。
- 安全审核、图片不可读、时长/画幅/提示词等明确入参错误直接返回，不重复提交，避免重复计费。
- 查询阶段继续使用创建任务对应的鉴权配置；任务 ID 一旦返回就必须持久化并复用。

## 验收标准

1. 不传 `video_model` 时，业务选择规范化为 1.5 优先路径。
2. 显式传入 1.0 时，创建请求只使用 1.0 模型。
3. 四套候选配置按“同模型阶段内先轮转，再模型降级”的顺序执行。
4. 模拟 1.5 全部额度失败后，下一次请求的模型为 1.0；成功返回任务 ID 后不再重复创建。
5. 不支持的模型在网络请求前返回 `UNSUPPORTED_MODEL`。
6. 图片请求最终使用 `gpt-image-2`；编导层数据结构不增加模型选择字段。
