# 1256 编导层内部数据中心实施说明 v1.0

## 1. 定位

`DirectorContext` 是 Python 编排层内部的数据中心，不是新增 Coze 节点，也不是对外 API。它把已经产生的编导数据规范化为四类账本，再按原节点契约生成输入视图。

```text
原始节点输出
    -> DirectorContext
       -> NarrativeLedger
       -> TimingLedger
       -> ShotLedger
       -> VisualRouteLedger
    -> 原节点字段适配视图
    -> DirectorLockedManifest
```

## 2. 四类账本

| 账本 | 保存内容 | 主要适配视图 |
| --- | --- | --- |
| `NarrativeLedger` | `director_plan`、`segments`、`segment_beats`、视觉意图 | 102833 全文视觉意图 |
| `TimingLedger` | TTS 链接、大镜头时间线、总时间线、字幕时间线 | 165901、105880、156199 |
| `ShotLedger` | `Code_list`、`LLM_list` 和小镜头规划 | 197742、127095、103964、116616 |
| `VisualRouteLedger` | 语义视觉规格、画面路线、Host 选择结果 | 156199、139488、117861 |

## 3. 保持原节点契约

数据中心只负责内部复用。调用节点时仍然生成原来的字段：

- 102833 仍接收 `segments`、`director_plan`；
- 165901 仍接收 `links`；
- 105880 仍接收 `timelines`、`segment_text`、`all_timelines`；
- 103964 仍接收 `duration`、`items`、`segments`、`timelines`；
- 116616 仍接收 `Code_list`、`ref_image`、`segments`、`debug`；
- 156199 仍接收原来的六个字段。

因此，原节点名称、字段名、数组顺序、时间单位和失败分支不因数据中心而改变。

## 4. 优化结果

1. JSON 字符串只在节点边界解析，内部账本使用类型化对象。
2. `segments`、`director_plan`、`timelines`、`Code_list` 不再由编排器多处手工重组。
3. 节点输出仍写入原 `WorkflowRunResult.outputs`，审计结果保持兼容。
4. `VisualRouteLedger` 只保存语义视觉字段，不保存最终 `prompt`、模型或供应商请求参数。
5. `snapshot()` 只输出轻量计数和状态，适合记录数据中心状态，不复制完整原始响应。

## 5. 当前限制

本版本完成的是内部数据传输优化，不等于外部模型或插件在线验收。102833、159953、197742、116616、139488 等节点仍需真实 transport 验证；数据中心会继续保留它们的阻断状态，不伪造成功结果。
