# 1256 编导故事到素材提示词传递契约 v1

## 结论

编导层生成的 `cinematic_story` 不是仅供展示的文本。用户审核通过后，它必须沿着同一批镜头索引进入两个实际提示词节点：

```text
用户原文
  -> 编导故事草案
  -> 用户 approved
  -> DirectorLockedManifest.cinematic_story
  -> 116616 Shot_Visual_Arrangement
       -> 首帧图 prompt
       -> story_context[镜头索引]
  -> 170263 首尾帧顺延（只传递，不改写）
  -> 113743 提示词生成
       -> 视频素材 video_prompt
```

未审核的故事只能输出 `story_draft` 并停在 `STORY_REVIEW`，不能进入 `DirectorLockedManifest`、首帧生成或视频素材生成。

## 传递字段

`cinematic_story` 的核心数据来自：

- `movie_outline`：主角、目标、冲突、人物弧光、结尾悬念；
- `scene_groups`：连续场景、场景目的、可见冲突、转折和状态变化；
- `narration_mappings`：每个 `gXX` 与文案段落一一对应的语义映射、无对白动作、隐喻和下一段承接。

`116616` 将每个大分段的映射展开为每个小镜头的 `story_context`。首帧提示词至少使用场景目的、可见冲突、无对白动作、隐喻、前后状态和转折。

`170263` 保持该数组的原始小镜头顺序，只负责首尾帧数组重组，不允许丢弃故事字段。

`113743` 使用同一个小镜头位置的 `story_context`，把语义映射、默片动作、隐喻、状态变化、转折和承接加入 `video_prompt`。因此首帧和视频素材提示词共享同一叙事依据，但仍保留各自的画面和动作生成职责。

## 验收规则

- `story_context` 数量必须与对应提示词数量一致；
- 数组按 `gXX_sXX` 顺序一一对应，不允许按字典或场景名称重新排序；
- 没有 `story_context` 时，旧输入输出保持兼容；
- 有 `story_context` 时，唯一故事标记必须能在首帧 prompt 和 video prompt 中被检出；
- `DirectorLockedManifest` 的 `story_review_status` 必须为 `APPROVED`；
- 用户修改故事后必须递增 `story_revision`，并重新生成后续提示词；
- 数字人、BGM、特效和剪映写入不在本次改动范围内。
