# 1256 编导镜头媒体评分与条件加权草案 v0.1

状态：研究草案，供业务评审；尚未接入生产代码  
日期：2026-08-25  
适用范围：编导锁定后的逐镜**镜头分类与媒体轨道选路**

## 1. 草案结论

最终规则只分两类：

1. **硬性规则**：先排除绝对不能使用的候选，不参与分数补偿。
2. **评分规则**：由“基础评分 + 条件加权 + 相邻镜头转移分 + 全片状态修正”组成。

不再建立独立的“动态规则层”。所谓动态规则，统一改成评分规则中的条件加权。连续静态图合并也不再由事后处理器强行改写，而是生成一个“合并 AIGC 候选”，与其他候选一起评分。

同时，**镜头分类**不能再等同于单一媒体类型。v2 固定使用五种镜头分类：

| `shot_class` | 业务含义 | 主画面 | 叠加轨道 |
| --- | --- | --- | --- |
| `aigc` | 需要动作、过程或连续画面推进的叙事镜头 | AIGC 视频 | 无 |
| `image` | 单帧即可完整表达的状态、空间、物件或情绪落点 | 静态图片 | 无 |
| `digital_human` | 主播正面讲述、表态或建立信任 | 数字人视频 | 无 |
| `explanation` | 用可视化讲清因果、对比、流程、层级、时间线或数据关系 | 整屏说明画面/动效 | 无 |
| `mixed_explanation` | 既要讲清逻辑关系，又需要数字人以画中画补充讲述或建立可信度 | 整屏说明画面/动效 | 数字人画中画 |

因此，`mixed_explanation` 不是“数字人全屏 + 说明层”的旧 `overlay_explanation`。它必须是**说明关系为主画面、数字人为画中画**；数字人只是辅助轨道。

建议执行模型：

```text
冻结 STT/镜头坑位
  -> 硬性规则过滤候选
  -> 为五种 shot_class 候选计算基础分
  -> 根据前后镜头和全片状态计算条件加权
  -> 序列优化器选择全片总分最高的分类与轨道方案
  -> 硬性复检
  -> 生成唯一 media_route_lock
```

## 2. 为什么不能继续逐镜贪心选择

当前逐镜独立比较图片分和视频分，无法可靠处理以下问题：

- 第 4 张图片是否应该转视频，取决于前面已经选了什么；
- 数字人比例和全片媒体比例，取决于此前累计数量；
- 两个镜头是否合并，取决于相邻语义、合并时长及后续路线；
- 一个镜头单独看图片分最高，不代表放进整片后仍然最好；
- 同样的媒体类型连续出现，不一定重复；真正需要惩罚的是画面语义、景别、主体和构图的重复。

因此，最终目标应该是选择“全片总分最高的媒体序列”，而不是逐镜选择眼前最高分。

## 3. 硬性规则草案

| 编号 | 硬性规则 | 处理结果 |
| --- | --- | --- |
| H01 | STT 字幕 ID、顺序、原始文本和微秒时间线不得被媒体选路改写 | 不满足直接阻断 |
| H02 | 每个视觉坑位必须锁定一种 `shot_class` 和一种主画面；仅 `mixed_explanation` 可额外拥有一个数字人画中画轨道 | 多选、空选或混合说明缺轨道直接阻断 |
| H03 | 首个视觉坑位必须为 `aigc`，且主画面必须是 AIGC 视频；数字人不得作为首镜 | 仅保留 `aigc` 候选 |
| H04 | 普通视觉坑位目标时长为 2.5～5 秒；单个最终视觉坑位不得超过 5.5 秒 | 超限回到坑位规划拆分 |
| H05 | 两个短坑位允许共用一个视觉画面，但必须保留各自字幕；合并后不超过 5.5 秒 | 生成跨字幕视觉候选，不合并字幕 |
| H06 | 静态图必须无必要连续动作、无必要连续运镜，并能由单帧完整表达 | 不满足则排除图片候选 |
| H07 | `explanation` 必须声明逻辑关系类型和至少两个关系对象；`mixed_explanation` 还必须声明画中画窗口、锚点和数字人素材来源 | 字段缺失则排除说明类候选 |
| H08 | 数字人不得连续、不得用于空镜/纯意象/纯物件镜头；纯数字人和混合说明中的数字人曝光时长合计不得超过全片 15% | 不满足则排除数字人或混合说明候选 |
| H09 | 条件加权或合并候选不能越过 H01～H08 | 最终结果再次复检 |
| H10 | 下游素材、视频提示词和剪映写入只能读取当前版本的 `media_route_lock` | 旧版本仅可查看，不得继续生产 |

说明：原“低于 3 秒强制静态图”不再是硬性规则。短镜头先由坑位规划执行 `<2.5 秒优先合并`，媒体类型继续参加评分。

## 4. 基础评分模型

### 4.1 统一评分维度

五种镜头分类候选必须使用同一组评价维度，否则不同分类的总分不可直接比较。

| 维度 | 权重 | 评价问题 |
| --- | ---: | --- |
| C01 叙事表达匹配 | 25 | 该分类是否最清楚地表达当前事实、动作、观点或情绪？ |
| C02 运动表达匹配 | 15 | 当前内容对连续动作、人物运动或运镜的需要有多强？ |
| C03 逻辑关系表达匹配 | 20 | 因果、对比、流程、层级、时间线或数据关系是否需要被可视化？ |
| C04 注意力与节奏贡献 | 15 | 该分类是否让当前位置的节奏更合适，而非机械刺激？ |
| C05 前后镜头连续性 | 10 | 主体、动作方向、空间和语义能否自然承接？ |
| C06 视觉差异与信息覆盖 | 5 | 是否增加新信息，并避免与邻近镜头重复？ |
| C07 生产可行性与稳定性 | 10 | 参考图、人物一致性、说明模板和生成风险是否可控？ |
| **合计** | **100** | — |

每个候选在每个维度使用 `0 / 25 / 50 / 75 / 100` 五档证据分，再按权重计算：

```text
基础分 = Σ（维度证据分 × 维度权重）÷ 100
```

模型只负责抽取“存在动作、说话主体、情绪强度、画面是否单帧可表达”等事实；固定程序根据事实映射为证据分。模型不得直接返回最终总分或最终媒体类型。

### 4.2 五种镜头分类的评分锚点

| 事实 | AIGC | 图片 | 数字人 | 说明 | 混合说明 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 明确起点到终点动作、冲突升级、状态变化 | 高 | 低 | 仅正面讲述时中等 | 低 | 低至中 |
| 单帧即可完整表达的物件、空间、结果落点 | 中 | 高 | 低 | 低 | 低 |
| 主播必须正面解释、表态、建立信任 | 中 | 低 | 高 | 中 | 高 |
| 因果、对比、流程、层级、时间线或数据关系 | 中 | 低 | 低 | 高 | 高 |
| 既需要关系说明，又需要主播露出强化可信度 | 低 | 低 | 中 | 中 | 高 |
| 连续运镜或镜头内运动不可省略 | 高 | 0，硬规则排除 | 低至中 | 低 | 低 |
| 纯意象、空镜、物件特写 | 中 | 高 | 0，硬规则排除 | 低 | 0，硬规则排除 |
| 人物参考不足、复杂动作生成风险高 | 降分 | 视单帧可表达性加分 | 视数字人素材完整性评分 | 视模板数据完整性评分 | 需同时评估模板和数字人素材 |

说明类必须进一步输出固定的 `relation_type`：`causal`（因果）、`comparison`（对比）、`sequence`（流程）、`hierarchy`（层级）、`timeline`（时间线）、`data_trend`（数据变化）或 `concept`（抽象概念）。`template_id` 只能从该关系类型的白名单中选择。

### 4.3 说明与混合说明的轨道契约

说明镜头不是普通字幕、标题或“画面上多写几行字”，而是把文案中的逻辑关系变成可读的视觉结构。它们先输出 `shot_class`，再由固定映射确定模板和轨道：

```text
shot_class -> relation_type -> template_id -> template_version -> track_plan
```

| 分类 | 固定轨道结构 | 素材要求 | 不允许的退化 |
| --- | --- | --- | --- |
| `explanation` | 一条整屏逻辑关系说明轨道 | `relation_type`、关系对象、模板 props | 退化成普通静态图片或文字堆叠 |
| `mixed_explanation` | 整屏逻辑关系说明主轨道 + 一条数字人画中画轨道 | 说明模板全部字段 + 已确认数字人素材 + PiP 布局与出现时间 | 把数字人放成全屏底图，再盖一层说明 |

`mixed_explanation` 的数字人画中画必须输出：

```json
{
  "digital_human_asset_ref": "已确认的数字人素材引用",
  "pip_time_range": {"start_us": 0, "end_us": 2200000},
  "anchor": "top_right",
  "safe_area": "不得遮挡字幕和核心关系节点",
  "purpose": "补充解释 / 观点强调 / 建立可信度"
}
```

数字人在混合说明中的实际曝光时长为 `pip_time_range.end_us - start_us`。这段时长计入数字人 15% 上限；连续性检查也按真实曝光窗口计算。纯数字人镜头继续只生成口型同步、表情、机位和音频绑定数据，不生成首帧或 AIGC 提示词；混合说明同时拥有说明模板和已确认数字人素材，但不新建 AIGC 剧情视频。

## 5. 条件加权草案

条件加权只改变合格候选的分数，默认累计后限制在 `-40～+40`，避免某一条偏好吞掉全部基础判断。

### 5.1 开场视频倾向

| 条件 | AIGC | 图片 | 数字人 | 说明 | 混合说明 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第 1 镜 | 硬性保留 | 硬性排除 | 硬性排除 | 硬性排除 | 硬性排除 |
| 第 2～3 镜 | `+15` | `-15` | `+15`，仍受数字人硬规则限制 | `+5`，仅限有明确关系说明 | `+10`，仍受数字人曝光上限限制 |

这保证前三镜尽量是视频，但不会允许数字人连续或突破 15% 上限。

### 5.2 连续静态图加权

建议采用“第 3 张预警、第 4 张强触发”，避免等到画面已经形成幻灯片后才处理。

| 进入当前坑位前已连续出现的静态图数量 | AIGC / 说明 / 混合说明 | 数字人 | 静态图片 | 说明 |
| ---: | ---: | ---: | ---: | --- |
| 0～1 | `0` | `0` | `0` | 不干预正常图片使用 |
| 2 | `+5` | `+2` | `-5` | 轻度预警 |
| 3 | `+15` | `+5` | `-15` | 尽量避免第 4 张图片 |
| ≥4 | `+30` | `+10` | `-30` | 强烈倾向动态或逻辑关系画面，仍不越过硬性可行性 |

若已经形成 4 张连续静态图，且最后两个镜头满足：

- 同一语义组；
- 语义连续；
- 合并视觉时长不超过 5.5 秒；
- 合并后可以用连续视频表达；

则新增 `merged_aigc_video` 候选，该候选额外 `+25`。它消耗两个视觉坑位，但原字幕、旁白及其时间线仍保留两条，只建立 `source_caption_ids -> visual_slot_id` 的多对一映射。

### 5.3 全片视觉轨道分布修正

比例用于软引导，不作为静态图/AIGC 的硬配额。五种镜头分类存在“混合说明包含数字人画中画”的重叠，因此不能再沿用旧的 `AIGC / 图片 / 数字人 = 60% / 30% / 10%` 分类配额。初始建议改为按主画面和数字人曝光分别统计：

| 统计维度 | 建议中心值 | 建议观察区间 |
| --- | ---: | ---: |
| AIGC 主画面 | 55% | 45%～65% |
| 静态图片主画面 | 25% | 15%～35% |
| 说明主画面（包含混合说明） | 20% | 10%～30% |
| 数字人实际曝光时长（纯数字人 + 画中画） | 10% | 5%～15%，15% 为硬上限 |

序列计算到第 `i` 个坑位时，比较“截至当前位置的期望数量”和“已选择数量”：

```text
分布修正 = clamp((期望数量 - 已选数量) × 5, -15, +15)
```

开场前三镜只执行开场规则，不启用全片比例修正，避免短序列初期比例波动过大。

### 5.4 叙事状态加权

| 条件 | 加权建议 |
| --- | --- |
| 动作推进、矛盾揭露、关系变化、强情绪峰值 | AIGC `+10`，静态图 `-10` |
| 主播必须正面解释、表态或建立权威 | 数字人 `+12` |
| 文案核心是因果、对比、流程、层级、时间线或数据关系，且需要被看懂 | 说明 `+15` |
| 在逻辑关系说明中，主播露出能显著补充可信度、观点强调或讲解节奏 | 混合说明 `+20`；不能仅因存在数字人候选就加分 |
| 空间建立、物件特写、信息展示、情绪停顿、结果落点 | 静态图 `+8` |
| 同主体、同景别、同构图连续重复 | 当前候选 `-5/-10/-15` 逐次递增 |
| 与上一镜动作方向、主体位置或语义交接自然闭合 | 当前候选 `+5～+10` |
| AIGC 复杂动作或人物一致性风险高 | AIGC `-5～-20`，必须记录风险证据 |

“同媒体连续”本身不直接扣分；只有画面主体、景别、构图或叙事功能重复才扣分。

## 6. 全片序列选择方法

推荐使用小规模 Beam Search（初始保留前 16 条候选路径），不再按镜头逐个贪心锁定。

每条候选路径需要保存：

```text
当前镜头索引
上一镜 shot_class 与主画面类型
连续静态图数量
数字人实际曝光时长
三类主画面累计数量（AIGC / 图片 / 说明）
上一镜主体/景别/构图标签
累计基础分、条件加权和转移分
```

普通候选消耗一个坑位；`merged_aigc_video` 消耗两个相邻坑位。遍历结束后选择全片总分最高且通过全部硬规则的路径。

当第一名与第二名分差 `<5` 时标记为低置信度，但仍按固定顺序完成确定性选择：

1. 硬规则余量更安全；
2. 视觉重复更少；
3. 基础分更高；
4. 最后使用固定媒体枚举顺序打破完全相同的平局。

## 8. 历史数据校准方案

第一轮不调用任何付费 API，只读取已保存的编导锁、STT 时间线和历史媒体路由离线重放。

建议至少抽取 10 条历史任务、150 个以上镜头，逐镜记录“接受/改为 AIGC/改为图片/改为数字人/改为说明/改为混合说明/应合并”。初始验收指标：

| 指标 | 草案目标 |
| --- | ---: |
| 硬规则违规 | 0 |
| 首镜 AIGC | 100% |
| 前三镜视频率 | ≥85% |
| 可修复条件下连续 4 张及以上静态图 | 0 |
| 数字人连续 | 0 |
| 数字人比例超过 15% | 0 |
| 说明镜头缺少 `relation_type`、关系对象或模板 | 0 |
| 混合说明缺少数字人画中画素材、窗口或安全区 | 0 |
| 数字人画中画遮挡字幕或核心关系节点 | 0 |
| 人工逐镜首次接受率 | ≥80% |
| 所有权重同时上下浮动 20% 后，路线变化率 | ≤10% |

最后一项是敏感性测试：如果权重轻微变化就导致大量镜头换类型，说明评分体系不稳定，不能进入生产。

## 10. 研究依据

- [UK Government MCDA guidance](https://www.gov.uk/government/publications/green-book-supplementary-guidance-use-of-multi-criteria-decision-analysis/use-of-multi-criteria-decision-analysis-in-options-appraisal-of-economic-cases)：先定义独立、可测量的评价标准；使用统一尺度、加权总分，并通过敏感性分析验证排序稳定性。
- [Stanford / Adobe: Computational Video Editing for Dialogue-Driven Scenes](https://graphics.stanford.edu/papers/roughcut/)：把剪辑习惯编码为序列模型，根据相邻状态而非单镜头独立选择画面。
- [CVPR 2015: Video Summarization by Learning Submodular Mixtures of Objectives](https://www.cv-foundation.org/openaccess/content_cvpr_2015/papers/Gygli_Video_Summarization_by_2015_CVPR_paper.pdf)：联合优化相关性、代表性和多样性，并惩罚冗余。
- [UAL: The Attentional Theory of Cinematic Continuity](https://ualresearchonline.arts.ac.uk/id/eprint/21187/)：镜头连续性依赖注意力在切镜前后的自然交接，支持把动作方向、主体位置和语义承接纳入转移分。
- [Narrative theory and the dynamics of popular movies](https://pmc.ncbi.nlm.nih.gov/articles/PMC5133278/)：局部镜头时长与叙事强度相关，说明时长应参与节奏评分，而不应简单决定媒体类型。
- [Effect of Subtitles on Gaze Behavior during Shot Changes](https://pmc.ncbi.nlm.nih.gov/articles/PMC10723748/)：字幕会显著改变切镜时的观看注意力，支持保持字幕时间线独立，并避免在字幕切换处进行无依据的高频画面刺激。

## 11. 待业务确认的八项参数

1. AIGC / 静态图片 / 说明主画面的软目标中心值是否采用 `55% / 25% / 20%`；
2. 连续图片是否采用“第 3 张预警、第 4 张强触发”；
3. 前三镜是否采用 AIGC `+15`、数字人 `+15`、说明 `+5`、混合说明 `+10`、图片 `-15`；
4. 合并 AIGC 候选是否采用 `+25`；
5. 敏感性测试的路线变化率上限是否采用 `10%`。
6. 混合说明的数字人画中画是否只允许出现在说明主画面的前半段或关键结论段；
7. 混合说明的数字人最大实际曝光时长是否固定为当前坑位的 60%，还是由模板按关系类型决定；
8. `relation_type` 的七类白名单是否足够，还是需要单列“问题—解法”关系。

这八项确认后，才能冻结 `media_route_scoring_v2` 并开始替换、回归和旧代码归档。
