# 1256 镜头媒体分类治理方案 v1.0

> **历史方案 / 已停止作为新实现依据 / 禁止重新接回生产链路。**  
> 本文包含已被否决的“低于 3 秒强制静态图”和独立连续静态纠偏思路。当前待评审方案见《1256 编导镜头媒体评分与条件加权草案 v0.1》。在 v2 评分器完成切换前，生产代码仍可能保留部分旧实现；不得据本文恢复或新增旧调用。

## 1. 结论

当前工程的三类媒体为：

- `digital_human_video`：数字人视频；
- `aigc_video`：AIGC 连续视频；
- `static_image`：静态图片首帧。

本方案将“图片是否使用”从模型描述字段中独立出来，统一由一个确定性路由器决策。模型只能提供事实和候选，不能直接改变最终媒体类型。最终结果必须逐镜唯一、可解释、可回放，并在进入素材生产前冻结。

本方案针对的是镜头媒体分类，不改变镜头 ID、镜头顺序、时间线或下游素材接口。

## 2. 当前实现审计结论

当前工程已经具备一部分治理基础：

- `src/workflow_1256/cinematic_storyboard_governance.py` 已有低动势、可见动作、固定机位、短镜头和数字人候选逻辑；
- `resolve_cinematic_media_routes()` 已将每个镜头收口为一种媒体类型；
- `src/workflow_1256/governance/director_media_route_lock.py` 会校验时间线、数字人首镜禁用、图片资格和下游跳过动作；
- 数字人还有独立的占比、非连续、精确坑位校验。

当前主要问题不是完全没有规则，而是规则分散且解释不足：

1. `shot.route_candidates`、`production_spec.selected_route`、`shot_context.media_type` 都可能出现媒体判断，但没有统一声明“谁是事实、谁是候选、谁是最终结果”；
2. “固定机位”“低动势”“没有连续运镜”容易被误当成“没有可见动作”；
3. 图片的短时长规则、低动势规则和数字人候选规则没有以同一张优先级表呈现；
4. `media_reason` 目前主要是说明文本，不能完整记录命中的规则、被排除的候选和冲突来源；
5. 下游仍需要依赖 `skip_*` 推断分支，缺少一个可审计的逐镜决策记录。

现状差异：当前 `_route_candidates()` 为兼容历史清单，会把
`production_spec.selected_route` 追加到候选集合。按本治理方案，未来应改为：
`selected_route` 只能表达编导意图，数字人必须同时出现在明确授权的
`route_candidates` 中；否则记录 `UNDECLARED_DIGITAL_HUMAN` 并拒绝新增数字人坑位。
在这条规则代码化前，不能把当前实现宣称为治理方案的最终实现。

## 3. 字段职责与唯一来源

| 数据 | 来源 | 职责 | 是否能直接决定最终类型 |
| --- | --- | --- | --- |
| `timeline.start_us/end_us` | `DirectorLockedManifest` | 计算镜头时长，单位必须是微秒 | 是，参与硬规则 |
| `route_candidates` | 冻结镜头/`production_spec` | 表示允许考虑的候选路线 | 否 |
| `selected_route` | 冻结镜头 `production_spec` | 表示编导明确锁定的路线意图 | 仅数字人可作为强候选，仍需过硬规则 |
| `source_text`、`story_beat`、`blocking`、`must_show`、`story_mapping` | 编导及冻结镜头 | 判断是否存在可见动作或连续叙事 | 是，参与资格判断 |
| `dynamic_level` | 编导治理上下文 | 低/中/高的辅助事实 | 不能单独覆盖可见动作 |
| `visual_direction.camera_motion` | 编导治理上下文 | 判断是否需要连续运镜 | 是，参与图片资格判断 |
| `shot_context.media_type` | 模型治理输出 | 回显路由结果 | 否，必须与路由计划一致，否则拒绝 |
| `media_type` | `resolve_cinematic_media_routes()` | 唯一最终分类 | 是 |
| `decision_code`、`evidence` | 路由器新增审计字段 | 解释决策和冲突 | 不参与决策 |

原则：`shot_context.media_type` 不是权威来源；模型返回的类型只能与路由器结果逐字比对，不能反向改变路由器结果。

## 4. 三类媒体定义

### 4.1 数字人视频

适用条件：

- 镜头具有 `host`、`digital_human` 或 `digital_human_video` 候选；
- 不是第一个镜头；
- 时长不低于 3 秒；
- 不超过全片数字人镜头占比上限，当前默认是 15%；
- 不与另一个数字人镜头连续；
- 数字人时间窗必须精确等于锁定镜头时间窗。

数字人适合承担正面解释、关键结论、信息触发等“主播必须出现”的表达，但不应覆盖整段内容，也不能占用空镜、意象镜头或纯物件镜头。

### 4.2 AIGC 视频

适用条件：

- 有人物或物体的可见动作；
- 有动作推进、关系变化、冲突升级或结果变化；
- 需要连续运镜：推近、拉远、横移、跟拍、摇镜、环绕；
- 不满足图片资格，且不满足数字人资格。

AIGC 视频是“需要连续运动表达”的默认路线，不应仅因存在一个静态画面或一个参考图就使用图片替代。

### 4.3 静态图片

静态图片不是“模型没有判断出来时的兜底”，而是满足以下任一条件的明确路线：

1. 短镜头：时长 `< 3 秒`。这是当前工程的硬路由规则，用于快速切换；即使历史字段残留了运镜词，也不进入 AIGC 视频；
2. 低动势镜头：时长 `3 秒至 5 秒`、固定机位、无可见动作、无连续运动要求，并且属于空间建立、物件特写、信息展示、状态观察、情绪停顿、结果落点等低动势职责。

图片不得用于：

- 需要展示起点到终点动作的镜头；
- 人物明显移动、冲突升级、关系变化的镜头；
- 明确需要连续运镜的镜头；
- 超过 5 秒且没有拆镜的镜头；
- 被明确锁定为数字人且同时满足数字人硬约束的镜头。

注意：“固定机位”只表示摄像机不动，不表示画面没有动作。`blocking`、`must_show`、`source_text` 或 `story_mapping` 中出现“推开、走向、递给、打开、起身、转身”等可见动作时，必须优先判为 AIGC，除非命中短镜头硬规则。

## 5. 唯一优先级与决策顺序

路由器必须严格按以下顺序执行，不能由模型自行调换：

| 优先级 | 规则 | 结果 | 决策码 |
| --- | --- | --- | --- |
| P0 | 输入缺失、时间线无效、数组无法一一对应 | 阻断，不生成素材 | `BLOCK_INVALID_INPUT` |
| P1 | 时长 `< 3 秒` | 静态图片，跳过 AIGC | `IMAGE_SHORT_SHOT` |
| P2 | 第一个镜头 | 禁止数字人；继续判断图片或 AIGC | `FIRST_SHOT_NO_DIGITAL_HUMAN` |
| P3 | 数字人锁定意图且通过候选、时长、占比、非连续校验 | 数字人视频 | `DIGITAL_HUMAN_LOCKED` |
| P4 | 存在可见动作、动作推进、冲突升级或连续运镜 | AIGC 视频 | `AIGC_VISIBLE_MOTION` |
| P5 | 3 至 5 秒、固定机位、无可见动作、低动势职责 | 静态图片 | `IMAGE_LOW_MOTION` |
| P6 | 其他合法镜头 | AIGC 视频 | `AIGC_DEFAULT` |

这里的关键关系是：

- P1 是当前工程的时长硬规则，优先于其他媒体路线；
- P2 是数字人的位置硬规则，不代表首镜一定是图片；
- P3 只对通过硬校验的数字人坑位生效；
- P4 的可见动作优先于 `dynamic_level=低` 和 `camera_motion=固定`；
- P5 是图片的正常低动势入口；
- P6 保证无法证明为图片或数字人的镜头不会被误降级。

可执行决策树：

```text
输入有效？
  否 -> BLOCK_INVALID_INPUT
  是 -> 时长 < 3 秒？
          是 -> static_image / IMAGE_SHORT_SHOT
          否 -> 首镜且数字人候选？
                  是 -> 禁止数字人，继续判断
                  否 -> 数字人锁定且通过治理？
                          是 -> digital_human_video / DIGITAL_HUMAN_LOCKED
                          否 -> 存在可见动作或连续运镜？
                                  是 -> aigc_video / AIGC_VISIBLE_MOTION
                                  否 -> 低动势图片资格？
                                          是 -> static_image / IMAGE_LOW_MOTION
                                          否 -> aigc_video / AIGC_DEFAULT
```

## 6. 冲突处理

冲突不能靠改写 `media_reason` 解决，必须输出结构化结果。

| 冲突 | 处理 | 记录 |
| --- | --- | --- |
| `selected_route=digital_human` 但时长 `< 3 秒` | 图片胜出 | `overridden_candidates=["digital_human_video"]` |
| `selected_route=digital_human` 但为首镜 | 禁止数字人，重新判断图片/AIGC | `conflict=FIRST_SHOT_DIGITAL_HUMAN_FORBIDDEN` |
| `dynamic_level=低` 但 `blocking` 有可见动作 | AIGC 胜出 | `conflict=VISIBLE_ACTION_OVERRIDES_LOW_DYNAMIC` |
| `camera_motion=固定` 但人物有起点到终点动作 | AIGC 胜出 | `conflict=FIXED_CAMERA_IS_NOT_NO_ACTION` |
| `route_candidates` 没有数字人，但 `selected_route` 写了数字人 | 不得自动新增数字人候选 | `conflict=UNDECLARED_DIGITAL_HUMAN` |
| 模型 `media_type` 与路由器结果不一致 | 拒绝治理输出，要求重跑或回退确定性基线 | `BLOCK_MEDIA_TYPE_MISMATCH` |
| 镜头超过 5 秒且想使用图片 | 不允许图片，先回到分镜拆镜 | `BLOCK_IMAGE_DURATION_OVER_MAX` |

## 7. 建议新增的逐镜审计字段

在不改变现有下游字段的前提下，给 `decisions` 和 `shot_contexts` 增加以下字段：

```json
{
  "shot_id": "g01_s01",
  "media_type": "static_image",
  "media_reason": "镜头时长低于 3 秒，使用静态图片完成快速切换",
  "decision_code": "IMAGE_SHORT_SHOT",
  "decision_priority": "P1",
  "evidence": {
    "duration_us": 2500000,
    "camera_motion": "跟拍",
    "dynamic_level": "中",
    "visible_action": true,
    "route_candidates": ["scene"]
  },
  "overridden_candidates": ["aigc_video"],
  "source_fields": ["timeline", "source_text", "blocking", "visual_direction.camera_motion"],
  "downstream": {
    "create_first_frame": true,
    "create_aigc_video": false,
    "create_digital_human": false
  }
}
```

要求：

- `evidence` 只记录事实，不写模型自由解释；
- `decision_code` 必须来自固定枚举；
- `overridden_candidates` 只记录实际出现过但被规则排除的候选；
- `source_fields` 用于回溯字段来源；
- 原有 `media_type`、`media_reason`、`skip_*` 保留，保证下游兼容。

## 8. 代码落地边界

建议只保留一个最终决策入口：`resolve_cinematic_media_routes()`。

落地顺序：

1. 将 P0-P6 抽成命名清晰的纯函数，并让所有分支只返回 `decision_code` 和 `media_type`；
2. 路由器先生成完整 `decisions`，再由 `director_media_route_lock.py` 做契约校验；
3. `shot_context.media_type` 只做一致性校验，不再作为决策来源；
4. 下游素材生产只读取 `DIRECTOR_MEDIA_LOCKED` 结果，不重新判断媒体类型；
5. 将当前散落在 prompt、模型回传和下游 adapter 中的图片判断改为只读引用路由锁；
6. 历史兼容逻辑保留，但标记为“历史实现/兼容读取”，不得作为新项目的决策入口。

## 9. 必须覆盖的测试

至少新增以下表格驱动测试，每个测试都要检查 `media_type`、`decision_code`、被覆盖候选和下游跳过动作：

1. 2.5 秒、存在动作、候选 AIGC -> 图片，命中 `IMAGE_SHORT_SHOT`；
2. 3 秒、固定机位、无动作、低动势 -> 图片；
3. 4.5 秒、固定机位、`blocking` 为“推门” -> AIGC；
4. 4.5 秒、存在数字人候选、非首镜、未超占比 -> 数字人；
5. 首镜强制数字人 -> 禁止数字人，按图片/AIGC继续判定；
6. 相邻两个数字人候选 -> 只允许一个，另一个按 AIGC 或图片规则判定；
7. 5.1 秒低动势图片 -> 阻断或先拆镜，不能静态图片硬撑；
8. 模型返回类型与路由器类型不一致 -> `BLOCK_MEDIA_TYPE_MISMATCH`；
9. 输入镜头与上下文数量不一致或顺序错位 -> P0 阻断；
10. 全片媒体路由与首帧、AIGC、数字人、剪辑写入分支逐一对应。

## 10. 验收标准

治理方案落地后，必须同时满足：

- 每个合法镜头只有一个最终 `media_type`；
- 相同输入重复执行，分类结果、顺序和 `decision_code` 完全一致；
- 图片判断不再依赖模型自由发挥；
- 所有图片镜头都能说明是短镜头规则还是低动势规则；
- 所有被判为 AIGC 的镜头，都能指出动作、关系变化、冲突或连续运镜证据；
- 数字人镜头都能指出候选来源、坑位、占比和非连续校验结果；
- 下游不会为图片创建 AIGC 视频，也不会为数字人重复创建首帧和 AIGC 视频；
- 运行报告能按 `decision_code` 统计三类媒体数量和冲突数量；
- 离线测试通过后，仍需使用真实一次工作流输入检查最终路由 JSON、素材清单和剪辑草稿写入结果。离线测试不等于生产端到端完成。

## 11. 分阶段实施

### 阶段一：规则冻结

评审并确认本文件的 P0-P6 顺序、短镜头 `< 3 秒` 规则、低动势图片的 3-5 秒范围，以及数字人比例上限。

### 阶段二：审计字段

先新增 `decision_code`、`decision_priority`、`evidence` 和 `overridden_candidates`，不改变三类媒体的现有路由结果，观察真实样本中的冲突分布。

### 阶段三：单一入口

所有下游统一读取媒体路由锁；旧入口只保留兼容读取并打上历史标记。

### 阶段四：真实验收

使用一批真实工作流输入，逐镜检查路由 JSON、首帧生成清单、AIGC 任务清单、数字人任务清单和最终剪映草稿。只有这条闭环通过，才能称为生产链路完成。

## 12. 当前建议清理项

本轮不删除任何历史代码。后续确认新入口稳定后，再检查：

- 旧的直接读取 `shot_context.media_type` 并据此创建素材的入口；
- 旧的仅按图片比例限制图片数量的逻辑；
- 旧的把 `camera_motion=固定` 直接等同于“无动作”的判断；
- 旧的未经过媒体路由锁、直接进入 AIGC/数字人 adapter 的脚本。

清理前必须用全仓库调用检索和一次真实回归确认它们不再参与当前生产链路。
