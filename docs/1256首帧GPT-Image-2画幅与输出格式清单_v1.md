# 1256 首帧生图：GPT Image 2 画幅与输出格式清单

## 1. 当前模型与字段规则

- 首帧生图模型：`gpt-image-2`。
- 原生 Image API 的画幅字段是 `size`，值为像素尺寸字符串，例如 `2048x1152`；不是直接传 `16:9`。
- `auto` 表示由模型自动选择尺寸。
- 当前项目的旧 Aishuch 适配层仍保留工作流历史字段 `size="9:16"` 的兼容行为。扩展新画幅时，必须由画幅选择器统一映射为尺寸，再由适配层决定是否转换为代理格式。

## 2. 官方列出的常用尺寸

| 画幅比例 | `size` 示例 | 方向/用途 | 备注 |
|---|---:|---|---|
| `1:1` | `1024x1024` | 方形 | 常用、生成速度通常较快 |
| `3:2` | `1536x1024` | 横向 | 官方常用尺寸 |
| `2:3` | `1024x1536` | 纵向 | 官方常用尺寸 |
| `1:1` | `2048x2048` | 方形 2K | 大尺寸；2K 输出当前按实验性尺寸处理 |
| `16:9` | `2048x1152` | 横向 2K | 视频横版 |
| `16:9` | `3840x2160` | 横向 4K | 最大边达到官方上限 |
| `9:16` | `2160x3840` | 纵向 4K | 视频竖版 |
| 自动 | `auto` | 自动 | 官方默认值 |

## 3. 约束内可用的自定义比例

模型不是只支持上表中的 8 个字符串。只要满足官方尺寸约束，就可以使用自定义 `width x height`：

- 宽、高都必须是 `16` 的整数倍；
- 单边最大 `3840px`；
- 长边与短边的比例不超过 `3:1`；
- 总像素不少于 `655,360`，不超过 `8,294,400`。

因此项目的画幅选择器可提供下列常用比例，并在提交时映射为合法像素尺寸：

| 比例 | 推荐映射尺寸 |
|---|---:|
| `9:16` | `2160x3840`（官方常用） |
| `16:9` | `2048x1152`（官方常用） |
| `1:1` | `1024x1024`（快速草稿）或 `2048x2048`（2K） |
| `3:2` | `1536x1024` |
| `2:3` | `1024x1536` |
| `4:3` | `1536x1152` |
| `3:4` | `1152x1536` |
| `4:5` | `1280x1600` |
| `5:4` | `1600x1280` |
| `2:1` | `2048x1024` |
| `1:2` | `1024x2048` |
| `3:1` | `768x2304` |
| `1:3` | `2304x768` |
| 自定义 | 通过上述四条约束校验后提交 |

`3:1` 和 `1:3` 是边界比例，虽然满足官方比例约束，但不建议作为默认视频画幅；只在用户明确选择时启用。

## 4. 输出文件格式

- `PNG`：默认格式，适合需要无损画质的首帧和角色资产。
- `JPEG`：支持，通常生成/传输更快；可设置 `output_compression`，范围 `0–100`。
- `WebP`：支持；可设置 `output_compression`，范围 `0–100`。

当前 `gpt-image-2` 不支持透明背景；不能把 `background="transparent"` 作为首帧或主角资产的有效配置。

## 5. 其他可配置项

- 质量：`low`、`medium`、`high`、`auto`。
- 背景：`opaque` 或 `auto`；透明背景不可用。
- 参考图：首帧可以继续接收参考图，主角资产图作为固定角色参考图追加到每个镜头的参考图集合。

## 6. 项目落地规则

1. 用户只选择简单的比例：`9:16`、`16:9`、`1:1`、`3:2`、`2:3` 等；不让用户填写宽高和复杂对象。
2. 编导层只保存一个项目级 `aspect_ratio`；首帧生成、图生视频和 Windows 剪映画布都从同一个画幅值派生。
3. 素材层把比例解析为 `image_size`（像素尺寸）并记录 `image_format`；剪辑层只消费已生成媒体，不重新猜测画幅。
4. Aishuch 代理对非历史 `9:16` 值的兼容性尚未逐项真实探测；在 UI 放开全部选项前，必须逐项完成创建/查询 smoke test。离线契约通过不等于代理真实支持。
