# 1256 首帧多宫格生成与数字人跳过契约 v1

## 1. 目标

首帧生成节点 `184922` 对普通镜头采用多宫格批量生成，生成后由本地裁切器恢复为单镜头首帧；数字人镜头不进入首帧生成，也不进入普通图生视频批处理。

这只是素材层的内部优化，不改变编导层已经锁定的镜头顺序、时间线和镜头 ID。

## 2. 多宫格硬约束

- 每个宫格的宽度完全相同、高度完全相同。
- 宫格之间间隙为 `0` 像素，契约字段固定为 `separation_px: 0`。
- 禁止分割线、白线、黑线、边框、留白隔断、阴影隔断、网格线和拼贴缝隙。
- 禁止在图中绘制宫格编号、文字、标题、标签或其他说明。
- 输出尺寸必须能被行数、列数整除；裁切器不猜测 padding，也不做模糊补偿。
- 用户选择的是最大 `grid_layout`：`2x2`（最多 4 格）或 `3x3`（最多 9 格），不是每个批次的强制固定布局。每个批次按剩余普通镜头数自动收敛到最小可容纳布局：1～4 个用 `2x2`，5～9 个用 `3x3`；例如选择 `3x3` 但尾批只剩 3 个镜头时，尾批改用 `2x2`，不再生成 6 个无效宫格。
- 输出同时保留 `requested_grid_layout`（用户选择）和 `grid_layout`（当前批次实际布局），并以 `layout_policy: "max_capacity_auto_downgrade"` 标识该策略。
- 请求图片服务时不发送任意的 `2048x1024` 等尺寸字符串，而是按网格方向映射到受支持的方形、横向或竖向画布；裁切以服务实际返回尺寸为准，并再次检查是否可整除。
- 裁切后的文件名包含原始 `shot_index`，不能按“去掉数字人后的连续序号”重排。

## 3. 数字人路由

以下任一显式字段可以标记数字人镜头：

- `is_digital_human: true`
- `selected_route: "host"` 或 `"digital_human"`
- `clip_role: "host"`
- `digital_human_shot_indices: [原始镜头索引...]`

数字人镜头的首帧输出位置保留为空字符串，并输出到 `skipped_digital_human_shot_indices`。普通镜头如果与数字人镜头相邻，其 `ref_image_e` 也置空，避免普通图生视频路线跨越数字人镜头建立错误的首尾帧连续性。

## 4. 节点字段

首帧批处理节点新增内部字段：

```json
{
  "shot_metadata": [],
  "digital_human_shot_indices": [],
  "grid_config": {
    "grid_layout": "2x2",
    "cells_per_grid": 4,
    "cell_width": 1024,
    "cell_height": 1024,
    "separation_px": 0
  }
}
```

输出增加：

```json
{
  "grid_batches": [],
  "skipped_digital_human_shot_indices": []
}
```

旧调用未提供上述字段时，仍按原来的单图 `image_url_list` 逻辑运行，不增加额外输出字段。

## 5. 当前验证边界

已完成代码级等尺寸布局、零间隙裁切、不可整除尺寸拒绝、数字人跳过、紧凑首帧数组恢复和旧节点回归测试。尚未调用真实 Image2 服务验证模型是否严格遵守无隔断提示词；真实 API 验收时仍需检查生成原图是否存在视觉隔断，并在发现隔断时拒绝进入裁切和后续视频生成。

## 6. 画幅与防分割带裁切

- 编导层只接收一个项目级 `aspect_ratio`，默认 `9:16`；当前首帧多宫格可选 `9:16`、`16:9`、`1:1`。2x2 和 3x3 只决定宫格数量，不把单格强行做成正方形。
- `aspect_ratio` 会同时约束每个宫格、整张网格原图、Image2 请求 `size` 和返回的 `grid_config`。例如编导层传入 `16:9`，每个单格和整张 2x2/3x3 网格都按 `16:9` 生成；不会继续沿用默认竖版。
- `cell_width/cell_height` 仅为旧调用兼容字段；新调用不应填写。若旧调用同时传入宽高和 `aspect_ratio`，两者比例不一致会在生成前拒绝，避免数据管路悄悄错画幅。
- 提示词同时约束单格画幅、整体画布、等宽等高、零像素生成间隙，并禁止白线、黑线、边框、网格线和拼贴隔断。

调用时由编导数据中心直接传入同一个比例：

```python
result = run_first_frame_grid_batch(
    shots,
    aspect_ratio=director_context.aspect_ratio,
    grid_layout="2x2",  # 或 "3x3"
    create_runner=create_runner,
    query_runner=query_runner,
    materialize_runner=materialize_runner,
)
```
- 生成原图仍按真实返回尺寸等分，不能写死模型返回的像素尺寸。
- 如果模型返回的宽高不是行列数的整数倍，切图器会从外侧居中丢弃最多 `columns-1` 或 `rows-1` 个余数像素，再对有效区域等分；不会把余数像素混入某一个单格，也不会因为代理返回的奇数尺寸直接阻断链路。
- `crop_equal_grid_image` 使用同一套代码完成切图：默认每个单格四边内缩 `3px`，可通过 `crop_inset_px=4` 改为 `4px`。
- 切图器会在内部边界附近自动探测连续的黑色、白色或中性分割带；探测到后按带宽的一半转换为安全内缩，并叠加到统一内缩中。
- 所有单格使用相同最终内缩，保证输出宽高完全一致；即使只有某一条边检测到分割带，也不会让中间格与边缘格尺寸不同。
- 如需关闭自动探测，可传 `auto_trim_separators=False`；如已知还需要额外安全边距，可传 `separator_trim_px=3` 或 `4`。

示例：

```python
assets = crop_equal_grid_image(
    raw_grid_path,
    output_dir,
    batch,
    crop_inset_px=3,
    auto_trim_separators=True,
)
```

- 使用本机 Image2 鉴权真实创建了一张新的 `2x2` 多宫格图；服务实际返回 `941x1672`，比例约为 `9:16`，不是旧测试中的方形原图。
