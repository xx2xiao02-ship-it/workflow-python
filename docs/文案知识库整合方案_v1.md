# 文案创作与账号知识库整合方案 v1

## 1. 结论

当前存在两层知识资产和两个页面产品来源：

- 本地生产控制台：`tools/video_production_console.py` + `src/workflow_1256`，作为唯一生产入口。
- Sites/Vinext 原型：`site-video-production-console/`，仅保留为展示/原型，不参与生产。
- 旧风格包：`outputs/style_packages`，产物是 `style_profile`。
- 新账号知识库：Obsidian Vault，产物是作品卡、观点库、Writing-DNA 和账号上下文。

整合目标不是删除旧产物，而是让“账号知识包”成为统一管理入口，内部继续分层保存事实、观点和表达风格。

## 2. 目标工作架构

```text
资料/主页/作品链接/本地文件
        |
        v
账号知识库导入层（Obsidian 待处理）
        |
        +--> 作品卡 / 来源证据 / 事实材料
        +--> 观点库 / 认知框架 / 判断标准
        +--> Writing-DNA / style_profile（表达规则）
        |
        v
账号知识包审核（账号级）
        |
选题中心 --> CONTENT_READY 正文 --> 文案草案
                                      |
                                      v
                              事实/观点/原创审查
                                      |
                              REVIEW_PENDING
                                      |
                              人工确认 promote
                                      |
                                approved_copy
                                      |
                                    编导层
```

## 3. 统一入口设计

### 生产入口

只保留 `http://127.0.0.1:8768/writing` 作为文案生产入口。

### 知识入口

文案页的“新增风格包”改名为“导入账号知识包”，进入统一导入流程：

1. 创建或选择 `account_id`。
2. 导入主页、作品链接或本地资料。
3. 生成作品卡、观点库和 Writing-DNA/style_profile。
4. 账号级审核通过后，才允许文案使用。

“专业知识库”继续保存公共事实资料，但不得冒充账号观点。

## 4. 数据契约

保留现有字段，新增统一组合关系：

- `account_id`：账号知识包身份。
- `work_id` / `source_url`：作品与证据来源。
- `style_profile_id`：语言表达规则。
- `topic_plan_id`：选题事实和观点组合。
- `rewrite_id` / `draft_id`：文案产物。
- `review_status`：`REVIEW_PENDING|APPROVED|BLOCKED`。
- `approved_copy`：唯一允许进入编导层的文案字段。

数组保持输入输出一一对应，所有时间字段继续明确单位；旧 `style_profile_id` 不删除，通过 `account_id` 关联。

## 5. 迁移阶段

### 阶段 A：冻结现状

- 冻结 `8768` 生产接口和现有 `style_profile` 数据。
- 标记 Sites 项目为非生产原型。
- 建立旧产物到 `account_id` 的映射表。

### 阶段 B：打通导入

- 配置 `ACCOUNT_KNOWLEDGE_VAULT_PATH`。
- 将“新增风格包”接入 `production_bridge.py`。
- 默认流程写入账号知识库，并保留旧风格包快照。
- 失败时明确返回 `account_knowledge_distillation_failed`，不伪造成功。

### 阶段 C：打通文案链路

- 修复 `source_content_id` 从选题治理页进入文案页的交接。
- 文案页读取已审核账号知识包，而不是只读取旧风格包列表。
- 统一执行“草案 → 人工审核 → approved_copy → 编导”。

### 阶段 D：回归与切换

- 旧案例改写链路保留兼容读取。
- 新账号知识包链路完成真实样例验收后，设为默认。
- Sites 原型只保留展示，不再作为生产功能宣传入口。

## 6. 不可破坏内容

- 不删除 `outputs/style_packages`、历史文案、采集记录和任务快照。
- 不改变 `approved_copy` 进入编导的门禁。
- 不绕过人工审核。
- 不把账号观点当作新闻事实来源。
- 不把 synthetic/离线测试当作真实模型或真实采集验收。

## 7. 验收标准

1. 从账号主页导入后，能看到同一 `account_id` 下的作品卡、观点库和风格规则。
2. 文案页能选择该账号知识包并生成草案。
3. 选题正文能自动带入文案页，不需要重复粘贴链接。
4. 未审核草案不能进入编导；审核后生成唯一 `approved_copy`。
5. 旧风格包和历史文案仍可读取和恢复。
6. 完成真实采集、真实模型、真实文件和编导交接测试后，才宣布整合完成。
