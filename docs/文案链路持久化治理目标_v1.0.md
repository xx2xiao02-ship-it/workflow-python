# 文案链路持久化治理目标 v1.0

制定日期：2026-08-23  
适用范围：`http://127.0.0.1:8768/writing`、文案任务接口、风格采集/恢复任务，以及写作页进入编导页的本地交接。

## 一、唯一生产边界

生产页面只有 `tools/video_production_console.py` 提供的 8768 主服务：

```text
http://127.0.0.1:8768/writing
http://127.0.0.1:8768/director
http://127.0.0.1:8768/assets
http://127.0.0.1:8768/editing
```

`http://localhost:3000` 是 Sites/Vinext 原型入口，登记为
`unmanaged_prototype`，只保留用于识别和回溯，不参与生产链路，不得由脚本、页面或“打开页面”动作自动跳转。每次打开生产页面前执行：

```powershell
python tools\console_entry_registry.py writing --check
```

成功条件是健康状态为 `ready`、服务名为 `video_production_console`、端口为 `8768`，并且 `entry_path` 指向当前工作区的 `tools\video_production_console.py`。

## 二、任务持久化契约

任何会启动线程、独立 worker 或外部接口调用的任务，必须遵守“先落盘、后执行”：

1. 创建任务时先写入 `AppData\Local\VideoProductionConsole\tasks\<task_id>.json`；
2. 写入失败返回 `503 task_persistence_failed`，不启动 worker，也不留下只有内存的假任务；
3. 每次状态、阶段、进度、结果和错误变化都更新同一快照；
4. 浏览器刷新只读取快照，不以页面脚本的异常推断后端失败；
5. 主服务重启后，`queued/running` 任务标记为 `interrupted`，保留输入和错误字段，只有人工点击恢复才重新执行。

运行环境受限时可设置 `VIDEO_CONSOLE_RUNTIME_ROOT` 指向可写的本机持久目录；服务会把新快照写入该目录，同时只读扫描旧的 AppData 任务目录，完成迁移期间的历史召回，不会删除或覆盖旧快照。

服务健康接口同时暴露当前任务运行时目录；由本地治理器重启且工作区已有
`.runtime-governance-live\data\VideoProductionConsole\tasks` 时，默认继续使用该项目持久目录，
避免自动重启后静默切回 AppData。若 `task_runtime_source` 与预期不一致，页面必须阻断任务上下文操作。

快照必须保留以下字段（兼容历史字段，不覆盖原有结果）：

`task_id`、`task_type`、`workflow_version`、`schema_version`、`state`、`stage`、`progress`、`message`、`input_fingerprint`、`created_at`、`updated_at`、`worker_entry_path`、`worker_pid`、`parent_task_id`、`archive_id`、`legacy_status`、`error_code`、`error_detail`、`lifecycle_status`。

## 三、生命周期与旧链路治理

任务按生命周期分为：

- `active`：仅 `queued/running`，供当前页面轮询；
- `recoverable`：服务重启中断或已有样本的可恢复失败；
- `archived`：已完成或不可恢复的历史记录；
- `superseded`：被新版本/新任务替代；
- `deprecated`：明确废弃但为兼容保留。

旧风格采集任务、旧快照和历史文案不删除。默认写作页只查询 `view=active`；需要召回时查询 `view=recoverable`，页面只显示“人工恢复入口”，不得自动重新调用抖音、转写或模型接口。历史数据的清理必须先登记到 `archive/<audit_id>/recall_manifest.json`，确认没有生产调用、兼容责任和恢复价值后再由人工批准。

## 四、幂等与错误隔离

- 文案任务由案例链接、风格包、改写目标、发布形式、时长和个性化创意字段生成稳定 SHA-256 指纹；相同指纹的 `queued/running` 任务直接复用，禁止重复调用模型。
- “`setRewriteProgress is not defined`”等浏览器脚本错误只能标记为 `ui_error`，不能写成后端 `failed`；页面应继续轮询任务接口，并在刷新后恢复状态。
- 后端 `failed/interrupted` 必须带 `error_code`、`error_detail`；网络、鉴权、参数、第三方接口和页面错误分别记录，不能混成一个“执行失败”。
- 只有审核通过的 `approved_copy` 才能进入 `/director`；旧草案和未通过草案不能覆盖当前审核版本。

## 五、验收门槛

每次治理变更必须完成并留存以下证据：

1. Python 编译和入口预检通过；
2. 任务创建前写入快照、重启后可读、恢复接口不自动触发；
3. 相同输入只生成一条活动文案任务；
4. 写作页不加载旧 `style_collection` 任务，人工恢复入口可见；
5. 页面脚本错误不会伪造后端失败，网络短暂中断会继续轮询；
6. `/writing` → 文案任务 → `approved_copy` → `/director` 至少完成一次真实本地链路验证；
7. 测试、真实运行、外部服务和付费接口分别报告，不能用 Mock、静态 HTML 或 HTTP 200 代替真实完成证明。

## 六、长期防复发机制

- 发布前固定执行 `console_entry_registry.py writing --check`；
- 新增任务类型必须补齐快照字段、生命周期、重启恢复和去重测试；
- 每次服务启动执行旧任务扫描，只做状态归类和可召回标记，不自动重跑旧链路；
- 每月检查入口登记、worker `entry_path`、任务目录和 recall manifest，发现重复入口先隔离再评估删除；
- 删除任何历史文件前必须得到人工确认，并记录原用途、当前调用方和可能影响。
