# 视频制作控制台入口治理规范 v1.0

## 目的

防止把原型页面、只读开发实例或历史实现误当成当前生产编导页面。

## 唯一生产入口

当前生产控制台由 `tools/video_production_console.py` 提供，主服务端口为
`8768`，健康接口为 `/api/executor/health`。

| 页面别名 | 生产地址 | 角色 |
| --- | --- | --- |
| `writing` | `http://127.0.0.1:8768/writing` | 主服务 |
| `director` | `http://127.0.0.1:8768/director` | 主服务 |
| `assets` | `http://127.0.0.1:8768/assets` | 主服务 |
| `editing` | `http://127.0.0.1:8768/editing` | 主服务 |

“打开编导页面”必须先解析 `director`，再预检主服务；不能通过搜索目录名、页面标题或任意 `app/page.tsx` 来猜测入口。

## 非生产入口

- `site-video-production-console/`：未纳入主服务登记的 Vinext/Sites 并行 UI，状态为 `unmanaged_prototype`，地址为 `http://localhost:3000`，不是生产入口。暂不删除，避免影响可能存在的 Sites 原型；任何生产打开动作都不得自动跳转到它。
- `tools/run_video_production_console_dev.py`：只读页面冒烟实例，默认使用 `8770`，状态为 `dev_read_only`；不得占用 `8768`。

## 标准预检

在打开页面或启动新实例前执行：

```powershell
python tools\console_entry_registry.py director --check
```

成功必须同时满足：

1. 健康接口返回 `status=ready`；
2. `service_name=video_production_console`；
3. `port=8768`；
4. `entry_path` 指向当前工作区的 `tools/video_production_console.py`；
5. 返回 URL 为 `http://127.0.0.1:8768/director`。

任一条件不满足时，只报告阻断原因，不自动启动其他页面来“代替”主入口。

如果当前执行环境限制 `AppData\Local` 写入，先为本机服务指定可写的持久化根目录（不会删除旧 AppData 快照）：

```powershell
$env:LOCAL_SERVICE_RUNTIME_ROOT = "C:\工作流运行时\service"
$env:VIDEO_CONSOLE_RUNTIME_ROOT = "C:\工作流运行时\data"
python tools\local_service_governance.py start --service video_production_console
```

主服务会把新任务写入该目录，并只读召回旧 AppData 任务；普通未受限 Windows 环境无需设置此变量。

当前工作区如果已存在 `.runtime-governance-live\data\VideoProductionConsole\tasks`，
8768 主服务在受本地治理器拉起时会自动把该目录作为项目持久运行时，并保留 AppData
只读回溯目录。健康接口会返回 `task_runtime_root`、`task_runtime_source` 和
`task_scan_dirs`；如果重启后这些字段回到 AppData，应先修复启动环境，不要继续从素材页提交任务。

## 验收与变更边界

- 入口登记和预检是只读操作，不创建工作流任务、不调用付费服务。
- 生产服务的健康检查、页面状态和代码入口必须分别记录，不能只凭 HTTP 200 声称业务链路完成。
- 删除或归档 `site-video-production-console/` 前，必须确认它不再承担 Sites 预览或发布职责。
- 文案任务的快照、重启恢复、去重和旧链路隔离要求见
  `docs/文案链路持久化治理目标_v1.0.md`；没有持久化和恢复证据，不能把页面 HTTP 200 当作业务完成。
