# 账号认知知识库与 V2 选题文案隔离实施方案 v1.0

## 1. 当前基线与核心判断

当前真实链路为：

```text
TrendRadar / TikHub
  -> 采用选题
  -> 正文采集达到 CONTENT_READY
  -> 文案生成进入 REVIEW_PENDING
  -> 人工审核
  -> 生成 approved_copy
  -> 现有编导、TTS、镜头、素材与剪映链路
```

现有风格包已经包含 L1 语言、L2 结构、L3 选题、L4 素材、L5 认知、L6 视觉，但其 L3-L5 是从整个样本压缩出的规则，不能回答“这条判断来自哪一篇作品、经历了什么推理、适用于什么事件”。因此新系统不继续扩充风格包，而是新增可追溯的“账号认知知识服务”。

基线测试：`test_topic_center_integration.py`、`test_topic_writing_governance.py`、`test_style_package.py` 共 43 项通过。

## 2. 隔离原则

1. 不删除、不停用、不修改现有 `/topic-center`、`/writing`、`/api/case-rewrites`。
2. 不重新启用历史 `TOPIC_CENTER_QUEUE_ENABLED=False` 队列。
3. V2 首阶段使用独立服务、独立页面、独立数据目录，不占用生产入口 8768。
4. V2 未经人工审核不能生成 `approved_copy`，不能进入后续编导链。
5. V2 验收通过后，只增加一个显式的单向交付适配器；原导演层仍只认现有 `approved_copy` 契约。
6. Obsidian 是人工管理和长期资产源；Python 运行时使用由 Obsidian 构建的本地索引，不在每次请求时遍历全部笔记。

## 3. 目标架构

```text
热点新闻 -> 新闻事实卡 -------------------------------+
                                                     |
Obsidian账号库 -> 本地索引 -> 分账号检索 -> 多博主认知透镜
                                                     |
                                                     v
                                           选题中心 V2 Lab
                                                     |
                                           可追溯选题方案
                                                     |
Writing DNA风格包 -----------------------------------+
                                                     v
                                           文案创作 V2 Lab
                                                     |
                                  草稿 + 观点依据 + 事实引用
                                                     |
                                               人工审核
                                                     |
                                  显式交付为现有 approved_copy
                                                     |
                                          原编导生产链
```

日常使用不需要打开管理页面。对外只保留一个文案入口 `POST /v1/news-to-copy`；它在服务内部完成新闻事实、目标账号知识检索和 Writing DNA 风格适配。`127.0.0.1:8790/` 与 `/ui` 仅作为本地隐藏式诊断页，不能视为生产工作入口。

## 4. 数据分层

### 4.1 Obsidian 目录

```text
账号知识库/
  accounts/<account_id>/
    account.md
    Writing-DNA.md
    raw_works/
    derived_works/       # 风格包派生作品，不能冒充 raw_works
    work_cards/
    cognition_cards/
    negative_cases/
    grade_cards/
  generated/
    approved/
    published/
```

Vault 路径通过 `ACCOUNT_KNOWLEDGE_VAULT_PATH` 配置，代码内不得写死本机路径。

### 4.2 单篇作品卡

每篇作品必须保留：

- `work_id`、`account_id`、标题、平台、原始链接、发布时间；
- 原始正文或字幕的本地来源；
- 事实、核心命题、切入角度、推理步骤、证据类型、反方观点、结论边界；
- `content_grade` 与 `performance_grade` 两套独立评级；
- `manual_reviewed`、`knowledge_status`、`retrieval_weight`；
- 蒸馏模型、提示词版本、蒸馏时间和内容哈希。

### 4.3 分级规则

| 等级 | 用途 | 正常检索权重 |
|---|---|---:|
| S | 账号代表作、核心认知证据 | 1.00 |
| A | 观点或结构稳定可复用 | 0.80 |
| B | 普通已发布作品，仅补充上下文 | 0.35 |
| C | 失败或错误案例，只用于避错 | 0.00 |

传播数据不能自动把作品升级为核心认知；S/A 必须经过人工确认。C 级只能进入负面案例检索，禁止进入正常观点生成。

## 6. 两个 V2 节点契约

### 6.1 选题中心 V2 Lab

输入：

- `event_card`：事件ID、标题、已核验事实、新闻来源、人物、时间、争议点；
- `target_account_id`；
- `reference_account_ids`；
- `retrieval_policy`：每账号召回数量、允许等级、领域和时间范围。

输出：

- `topic_plan_id`；
- `recommended_angle`；
- `author_lenses[]`：每位博主的判断框架，保持账号隔离；
- `consensus[]`、`conflicts[]`、`new_synthesis[]`；
- `evidence_refs[]`：必须包含 `account_id/work_id/source_url`；
- `fact_risks[]`、`missing_evidence[]`；
- `status=READY|REVIEW_REQUIRED|BLOCKED`。

硬规则：博主旧观点只能提供解读框架，不能代替新闻事实来源。

### 6.2 文案创作 V2 Lab

输入：

- 已审核或待审核的 `topic_plan_id`；
- `style_profile_id`；
- 受众、发布平台、目标时长和创作要求。

输出：

- `draft_id`、`draft_copy`；
- `claim_trace[]`：文案中的每个重要事实和观点对应新闻来源或知识卡；
- `knowledge_refs[]`、`style_application[]`；
- `unsupported_claims[]`、`review_flags[]`；
- `review_status=REVIEW_PENDING|BLOCKED`。

硬规则：节点本身不得输出 `approved_copy`。人工审核通过后，由单独的 `promote_v2_draft` 操作交付到现有审核文案契约。

## 7. 分阶段执行

### 阶段 0：冻结与契约确认

- 保存当前接口、状态机和关键字段基线；
- 明确 `CONTENT_READY -> REVIEW_PENDING -> approved_copy -> director` 不变；
- 为 V2 建立独立目录、服务端口和环境变量。

验收：旧页面、旧API和旧数据哈希未变化。

### 阶段 1：账号知识库底座

- 实现 Obsidian 仓库读写、Schema、路径安全、原子保存、版本与哈希；
- 建立作品卡、认知卡、评级卡和失败案例卡；
- 支持只读扫描和显式写回，默认不自动修改人工笔记。

验收：同一作品重复导入不产生重复ID；路径变更后可以重建；密钥和本机绝对路径不进入笔记。

### 阶段 2：作品蒸馏

- 首批选择 2 位博主，每位至少 30 篇完整作品，建议先准备 50 篇；
- 先生成逐作品认知卡，再生成账号级认知规则；
- 账号级每条规则必须记录支持它的 `evidence_work_ids`，证据不足只能标记低置信度。

验收：抽查 20 张卡，原文、事实、观点、推理和来源可回溯；不同账号不串库。

### 阶段 2.5：风格包派生作品回流与候选升级支线

- 读取现有风格包的作品提取、改写和审核记录，写入 `derived_works/` 与作品卡；
- 每条记录标记 `source_kind=style_package_derived`、`evidence_quality=DERIVED` 和 `REVIEW_PENDING`，不得伪装成完整原始作品；
- 生成不覆盖当前 Profile 的 `style-profile-upgrade-v1` 候选包，输出新旧差异、表达信号和证据作品编号；
- 离线阶段不调用模型；真实模型升级必须在原始作品、授权和费用确认后显式触发。

验收：重复执行不产生重复作品卡；候选包不改变现行风格包；候选包明确标记人工审核、原始证据和回测门禁。

### 阶段 3：本地检索服务

- 首版构建可解释的关键词/BM25 索引；语义向量索引作为二期可选能力，需单独确认 embedding 模型、运行环境和费用；
- 实现按账号、等级、领域、时间和状态过滤；
- S/A 优先，B 只补充，C 进入单独避错通道；
- 返回评分明细，不只返回文本片段。

验收：10条已知问题的预期作品进入前5；正常检索不返回C级；删除索引后可从Obsidian完整重建。

### 阶段 4：选题中心 V2 Lab

- 新闻先生成事实卡，再检索各账号认知；
- 分别输出博主视角、共识、冲突和新账号可采用角度；
- 页面展示“为什么推荐、引用了谁、证据在哪里、风险是什么”。

验收：每个推荐角度均有来源；事实与历史观点明确区分；知识不足时返回 `REVIEW_REQUIRED/BLOCKED`。

### 阶段 5：文案创作 V2 Lab

- 先锁定事实和观点蓝图，再加载 Writing DNA 完成表达；
- 审核模型检查事实、观点跳跃、混合人格、原创性和来源完整度；
- 草稿只进入人工审核，不自动跳转编导。

验收：重要事实100%进入 `claim_trace`；没有引用的新增事实阻断；多博主原句不得直接拼接。

### 5.1 现有 API 管理模型映射

账号知识库不新建 API 类型或凭据，复用 `story-writing` 通道的角色槽位：

| 知识库动作 | 角色槽位 | 约束 |
|---|---|---|
| 单篇作品蒸馏、账号级 Writing-DNA、新闻角度综合 | `CONTENT_ANALYZER_ARK_MODEL` | 只返回结构化规则，必须保留作品/新闻证据 |
| 结合目标账号 Writing DNA 生成草稿 | `STYLE_ADAPTER_ARK_MODEL` | 只能表达已锁定事实和观点 |
| 文案审核与公共兜底 | `STORY_WRITER_ARK_MODEL` 或显式 `COPY_REVIEW_*` 覆盖 | 只返回审核结论，不生成 `approved_copy` |
| 原有编导生产 | `DIRECTORS_V2_ARK_MODEL` | 保持在 V2 知识阶段之外 |

当前本地索引是确定性的中英文词项索引，首版不需要额外 embedding API。模型请求必须通过显式运行入口触发，创建 provider、导入语料、索引和检索均不请求外部模型。

模型槽位由 API 管理配置注入当前进程；当内容分析或风格适配没有独立 API Key 时，transport 会复用现有故事鉴权文档，仅切换对应角色的模型槽位，不读取或写回密钥。

### 阶段 6：评级与选择性写回

- 审核通过稿写入 `generated/approved`；
- 发布后补充真实数据，人工确定内容评级与传播评级；
- 通过 `grade-work` / `POST /v1/grade-work` 写回当前作品卡，并新增评级历史卡；
- S/A进入核心检索，B低权重归档，C进入失败案例；
- 未发布草稿、模型失败稿和重复内容不写入核心知识库。

验收：一篇作品只能有一个当前版本；评级变化有历史记录；生成内容不能未经人工审核自我强化。

### 阶段 7：与现有生产链交付

- V2 Lab整体验收后，增加显式 `promote_v2_draft`；
- 只把人工确认文本映射为现有 `approved_copy`；
- 不改变编导、TTS、镜头、素材和剪映输入字段。

验收：V2交付稿能被现有导演读取；原文案链仍能独立产生并交付 `approved_copy`；失败可关闭V2入口立即回退。

最终成功标准：

1. 来源追溯率100%；账号串库为0；正常检索C级内容为0。
2. 10条历史新闻中，至少7条能召回其真实采用过的核心判断或相近认知框架。
3. 与“仅风格包”基线盲测相比，至少6/10条在观点相关性和推理一致性上更好。
4. 新文案所有事实都有新闻来源，所有账号认知都有作品来源。
5. 真实人工审核、真实模型调用和现有 `approved_copy` 交付均通过后，才可称为端到端完成。

## 9. 费用与风险边界

- 代码、Schema、本地索引和离线测试不产生模型费用；
- 批量蒸馏、真实生成和审核会调用模型，执行前单独确认样本量和费用；
- Obsidian插件不是生产依赖，插件失效不影响Python读取Markdown；
- 未配置Vault、索引过期、新闻来源不足、模型失败时必须显式阻断，不得返回伪造成功结果。
